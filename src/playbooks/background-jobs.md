# 后台作业

作业属于当前工位，同工位各频道都能查看和取消，别的频道发起的在 `job op=list` 里标 `started in <频道>`。完成通知只回发起它的频道，且该频道仍须绑定本工位，所以不要等别的频道的作业。绑定到任务的作业记在该任务的看板上。

短命令同步执行；长构建、测试、下载和批处理用 `bash async:true` 释放聊天回合。**async 不延长 timeout**：默认仍是 300 秒，预计更久就显式传足够的秒数。

```json
{"command":"npm run test","async":true,"timeout":1800}
```

需要结果就保留默认通知；`notify:false` 只用于以后不需要结果的 fire-and-forget 工作，task 步骤里的作业不能关通知。

## 派发与收尾

启动后先完成互不依赖的工作或派发。在有完成唤醒的 DingTalk daemon 中，只剩等待时结束回合，不连续 poll 或建回访事件；没有 daemon 时，终端内嵌的运行时只在终端打开期间投递完成唤醒，不要依赖它托管待返回的作业。作业终态会带回退出码、耗时、输出尾部和完整输出路径。

**task 步骤里**启动的作业自动绑定到本任务，只剩等待时结束回合，作业结算会叫醒任务；聊天里启动的作业不属于任何任务。带超时的作业也是任务等外部条件的传感器（见 `task-lead.md` 的“等待”）。

`job op=list` 用于需要当前状态的判断；`poll ids=[...]` 只适合一次短等待或取回结果，最多约 30 秒，仍在运行不代表失败。明确取消用 `cancel ids=[...]`，取消由你发起，不再发送完成唤醒。

## 容量与持久性

运行中作业按工位合计最多 5 个；满额先等待已有结果，只有工作已不需要才取消。daemon 重启后会恢复跟踪并补发完成通知。

重要产物让命令写入目标文件。stdout 保留 24 小时后清理；收到失败或 lost 时先查真实产物和错误，再决定是否重跑。
