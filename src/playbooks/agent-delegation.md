# 普通角色委派

几次工具调用能完成的自己做。独立上下文、专用能力、有效并行或独立判断的收益足以覆盖派发与整合成本时才委派。你负责检查真实产物并交付；临时委派不因异步而建 task。

## 选择并派发

从系统目录筛可用角色、输入支持和执行边界，再按不确定性、错误代价与成本选档。做法明确、易检查且易恢复用低成本档，常规实施用主力档，关键取舍或难验证考虑高档。名字不证明能力，缺输入/权限不靠升级模型解决。

优先 `subagent {agent, task}`，角色决定工具、模型、预算和背景策略。没有合适角色先判断能否自己做，确需临时内置执行者且有 subagent_inline 才读 [inline 配置](delegation-inline.md)；不内联外部命令、改角色文件或换 bash 绕过配置。子代理不能继续嵌套派发。

`task` 必须自足，即使角色注入过背景：**结果 → 已核实证据 → 适用要求 → 路径与边界 → 验收和交付**。调查给现象与复现入口，不预设根因；实施给确认结论与约束；返工给已裁决缺陷、复现、已通过项与重验方法。只带影响决策或避免重复调查的材料，细节给可读指针，不写“按上文”。适用记忆正文写入 task；图片给绝对路径并确认 CLI/模型支持，不会继承聊天附件。

## 隔离与独立检查

显式传仓库绝对 workingDirectory；默认是父级实际 cwd，不代表隔离。Git 仓库内并行/隔离写用 `worktree:true`（write/work），返回 branch、headSha、changedFiles；先核对并合并再交付。

写委派持目录独占租约，read verifier 持共享读租约，主会话 write/edit 也检查冲突。按报错 runId 等待或换 worktree；bash 没有逐文件租约拦截，不能用它改写被占用的 checkout。mutates 是声明，外部权限边界仍是 CLI sandbox、账号和环境。

独立检查用 `purpose:"verify"`，不要求 task，exec 不支持。给原始要求/验收文件、待检版本与入口，要求只查不修，不将实现者总结当预期。优先独立取证，再考虑不同模型。内置 verifier 移除 write/edit，但带 bash 仍可写；只有无 bash 的内置 read 角色或强制只读的外部 CLI 提供只读边界。可写 verifier 持写租约，PASS 后仍查 diff。

## 处理结果

| 环境 | 返回与回流 |
|---|---|
| 聊天内置委派 | 本回合共享 10 秒快速返回窗口；超过或 /stop 后转后台，worker 预算不变 |
| task 步骤 | 自动绑定任务，item 仅在此有效；内置也确认启动即返回。持久化结果在完整工具批次后进入本步或唤起下一步 |
| 外部委派 | 确认启动即返回 runId，完成后自动回流 |

聊天派发不绑定任务；需要任务处理时 task_message 转达，由其负责人派发。结果已返回就检查；dispatched 只表示已启动，完成独立工作后结束回合，不轮询、重派或套 job/event 等待。结果只叫醒发起且仍绑定原工位的频道，其他频道的 run 不会叫醒你；subagent_list 可取工位真实状态。

结果状态、尾部与 output.md 路径是待核实数据。对照要求查产物、版本、diff、检查输出和缺口，VERDICT: PASS|FAIL 仅是判断材料。FAIL 区分缺陷与验证受阻，分别修复或补条件；已通过证据仍适用就复用，不因换检查者全量重跑。

失败、卡顿、lost、续接或租约清理时再读 [恢复与生命周期](delegation-recovery.md)。任务的等待、汇报和关闭由 `task-lead.md` 负责，无需为普通聊天委派读取整份任务指南。
