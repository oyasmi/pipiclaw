# 工位切换与持续宿主

仅当用户要分开项目/群的状态、切换工位或安排长期运行时读取。工位不是另一个助手，也不是权限边界。默认已获准的私聊、群和终端使用 default，各有独立对话；正常聊天无需提示绑定。

## 用户操作工位

以下是用户命令，不是模型工具，不能用文件写入模拟：

- /desk 查看；/desk new <名字> [目录] 创建。
- /desk cwd <目录> 设置实际工作目录；/desk bind <名字> 切换本频道归属。
- /desk archive <名字> 归档闲置工位；终端可用 pipiclaw tui --desk <名字> 操作。

切换只改变本频道此后归属，记忆/文件不搬，切回沿用原会话。原工位后台任务继续，汇报/提问暂存，文本事件暂停；切回后自动投递。改 cwd、换仓库或指定委派目录不是切换工位。

用户明确要求时可只读查别的工位；要修改它的记忆、任务、事件，请用户在绑定它的频道或对应终端操作。其他频道发起的 job/委派结束只叫醒那个频道，不会叫醒你。

## 持续运行

daemon 提供长期任务车道、job/委派结果回流和外部 run 重启对账，支持 DingTalk 与 Web API。没有 daemon 时 pipiclaw tui 内嵌运行时随终端退出而停止；退出后没有宿主接收结果或推进任务。长跑工作需要持续运行的 daemon，不把终端退出说成工作已取消或已完成。
