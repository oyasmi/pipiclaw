# 聊天中的任务管理

适用于有 task_create 的普通聊天。task 承载需要跨回合持续管理目标、验收、预算和多步进展的项目；可以自行实施或按收益委派。几次调用、单次作业或临时委派不因异步而立项。定时或周期工作用 `event-scheduling.md` 的任务模板。

任务在当前工位的独立后台会话执行，与聊天并行；建档成功不表示项目完成。聊天管理和转达，不接管任务实施，也不在聊天派发后冒充任务已收到工作。

## 创建短而自足的任务

用 task_create，契约目标约 4 KB：

- goal：结果、范围、允许的外部动作、约束；创建即持续委托，Goal 与工具/security 一起限定授权。
- dod：客观验收标准，使用 `- [ ]` checklist，包含适用用户要求与必要检查。
- items：可选的独立交付分片，不复抄 DoD；每项应能独立派发和检查。
- budget：默认 steps 60、usd 20，包含绑定委派成本；未知费用不当零，步数预算仍生效。

依据创建结果告知 id 和用户命令 `/tasks show <id>`。任务负责人会收到契约，不必在聊天继续执行它的步骤。

## 管理现有任务

| 意图 | 操作与证据 |
|---|---|
| 查进度 | task_list 取当前状态、等待来源和在途工作；历史用 task_log，不能凭旧摘要声称最新进展 |
| 补要求、纠正或答问题 | task_message 原样转达；执行中进入当前步骤，否则留给下一步 |
| 暂停 | task_pause 中止步骤，委派/作业继续；用户 /stop 只停聊天 |
| 恢复 | task_resume；预算不足须追加，steps/usd 在已用量基础上增加；用户命令如 `/tasks resume <id> +steps 20` |
| 不再需要 | task_close outcome=cancel，连带取消在途工作；意图不清才问 |
| 已完成但待关闭 | 优先让负责人核实并汇报收尾；聊天只能关闭满足工具门禁的空闲任务，不能绕过未完成 DoD 或交付 |

同工位任一频道可管理，报告/提问发任务自己的投递频道。换绑后任务继续，投递暂存；切回或用户命令 `/tasks adopt <id>` 后送达，不把别的频道的汇报说成本聊天已交付。

只在确有缺项阻止当前工作时问用户；已有授权不重复确认。步骤执行、等待、验收和关闭协议由后台负责人读取 `task-lead.md`，聊天管理无需预读。
