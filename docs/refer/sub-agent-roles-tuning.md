# 子代理角色设定调优记录（2026-08-28）

对 `examples/sub-agents/` 全部 11 个角色的行为指导小节（工作方式 / 边界，以及承担同样职能的：接手姿势、单元验证、验证方法、事实纪律、组织方式、查询原则、筛查方法、调查方法、git-committer 的分步小节）做了一轮重写。`description`、frontmatter 和 `交付` 契约未改动。改动本身见 git diff，这里只记录判断依据。

## 三条贯穿全目录的原则

**删掉运行时已经提供的东西。** 「先读当前目录适用的仓库指令」原本出现在 planner / builder / builder-hard / verifier / worker / documenter 六个外部角色里——Claude Code 自动加载 `CLAUDE.md`，Codex 自动加载 `AGENTS.md`，这行指令让模型开局去重读它系统提示里已有的内容。同理 verifier 正文里那段临时产物规则，`buildVerificationProtocol()`（`src/subagents/tool.ts`）在 `purpose=verify` 时本来就会注入。

**固定流程编号改写成排序原则。** verifier 的「预检 → 启动 → 冒烟 → 边界 → 回归」、log-sifter 和 explorer 的编号步骤，是把模型自己会做的检索与验证策略写成了必经仪式；任务形态一变，仪式就变成空转。改成说清排序依据（先证伪、先便宜、先风险高），路径选择还给模型。

**补上「什么时候该停」。** 这是本轮唯一往里加的东西，也是最大收益。builder 有 60 分钟墙钟、builder-hard 有 90 分钟、explorer 只有 24 次工具调用，却没有一条说明退出条件——一个卡住的实现者会把整个预算烧在盲试上并最终交付为零。

## 逐角色判断

- **planner**：删「先定义验收再拆解」的顺序仪式（交付模板已经强制这个顺序），改为陈述验收与拆解的耦合关系。合并出一条「方案和篇幅都匹配问题规模」——小改动不该产出七小节的完整契约，交付结构里不适用的小节允许直接省略。
- **builder**：新增升级线。同一失败连续两三次没修掉且根因不清时，带着已排除方向和最小复现交回，由主代理决定是否换 builder-hard——把「烧满 60 分钟零交付」换成「十几分钟后带证据交回」。「跑一项类型检查或构建」的配额写法改成意图表述（默认不跑全量套件）。分散的提交禁令收进独立的 `边界` 小节。
- **builder-hard**：`接手姿势` 与 `工作方式与边界` 重叠明显（两边都在说不覆盖既有改动、改动映射证据），重组为「定位根因 / 修改与验证 / 边界」。加两条 opus + xhigh 真正需要的：用最小实验证伪假设（强模型偏好纯推理通读，实际打一行日志更快更准），以及不许把「改完好像不复现了」写成修复。
- **reviewer**：删掉 `purpose=verify` / advisory attestation 那一大段——那是写给部署者的运行时说明，对「怎么挑出缺陷」零帮助，README 已讲得更清楚。加「按风险面而非文件顺序审」，并明确**允许质疑需求和验收标准本身**：原文只说「不报告需求外功能」，容易让模型以为需求不可质疑，恰好锁死了独立评审最值钱的能力。
- **verifier**：全目录过度规定最严重的一个。Cypress 的具体目录（`cypress/screenshots/`、fixtures、support、downloads）写进了通用模板，只对一个框架成立；「写锁不是宿主机权限沙箱」是讲给人听的架构说明。删掉这些，保留「不改被验证对象」这条真红线。加一条 60 分钟预算下最关键的判断：环境缺前置条件就尽快标阻塞，别把大半预算花在修环境上。
- **scout**：全部价值是快，而原文一个字没提预算。加两三轮的收敛线；只读沙箱的禁令式表述改成赋能式一句（诊断命令放心用），沙箱本身已经是硬边界。
- **worker**：数据口径八项清单压成一句——原文自己都要补「不适用的项目不必机械填充」，凡是需要免责声明的清单都说明它不该是清单。加「产出规模匹配问题规模」。`thinkingLevel` 曾建议由 `max` 降到 `high`，用户决定保留 `max`，未改。
- **documenter**：最长的文件，`事实纪律` 五条里有三条在换措辞讲同一件事，压到四条。`组织方式` 给了固定文档骨架又自己补「不生搬硬套」，属于自相抵消的条条框框，改成说清目标（先让人跑通最小路径，再给完整细节和边界）。加一条这个角色真正的失控点：不重排别人的文档结构。
- **explorer**：24 次工具调用 / 3 分钟的预算在正文里完全没体现。加「一轮宽搜 + 定点细读、能并发就并发」和「预算耗尽前先把已确认结论带回」——这个角色最难受的失败是超时截断、什么都没带回来。删掉「只使用 read/grep」（`tools` 白名单已是硬约束）。
- **log-sifter**：领域知识（首次异常 / 重复噪声 / 恢复节点 / 异常前最后一条正常记录 / 退出码 / OOM / 信号 / 截断堆栈）是全目录性价比最高的几行，原样保留；补一条实招——先 `grep -n` / `-c` 看量级和分布，再读上下文。禁止写入的那几条（重定向、`sed -i`、`truncate`）保留：这是唯一一个手握 bash 又长期对着生产日志的角色，一次 `>` 就是不可逆事故。
- **git-committer**：唯一一个「流程即价值」的角色，禁令基本原样保留。六个编号小节压成三节；§1 的「沿用仓库惯例」与 §3 重复，合并。提交粒度默认改为单 commit：原文的「按可独立解释的逻辑单元分组」在鼓励拆多个 commit，而每个 commit 都要 stage、核对、`git show`，在 20 次工具调用的预算里很快见底。
