# 使用杠杆（Leverage）

这里放的是**如何把 Pipiclaw 用出更大产出**的洞见与思考，不是功能说明。

顶层手册回答"这个功能怎么用"，`specs/` 回答"当时为什么这样设计"。中间缺的是一层：**已经会用了，怎么用才能真正放大产出。** 这个目录补这一层。

## 它和其他文档的区别

| 目录 | 回答什么 | 权威性 |
|---|---|---|
| `docs/` 顶层手册 | 这个功能现在是什么行为、怎么配 | 当前行为的权威 |
| `docs/specs/` | 当时为什么这样设计、替代方案为什么被放弃 | 历史记录，可能含已退役路径 |
| `docs/leverage/` | 会用之后，怎么用才能产出更多 | **观点与实践，不是契约** |

因此这里的文章：

- **可以有主观判断和取舍**，也可以给出"我建议你别这么用"这类结论；
- **不定义任何行为契约**，涉及机制时链接回顶层手册，不复述细节（复述会过期）；
- 与代码冲突时，**以代码和顶层手册为准**，并回来修正这里。

## 写什么

判断一篇是否属于这里，用两个问题：

1. 它讲的是**用法形状**（怎么组织工作、怎么划边界、什么该自动什么不该），而不是字段和参数？
2. 它是否包含一个**别人不会自己想到**的判断？纯粹的功能罗列和泛泛的"最佳实践"不收。

编号只表示写作顺序，篇与篇之间没有依赖，可任意跳读。
