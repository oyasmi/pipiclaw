# 从扳手到车床：让 Pipiclaw 持续产出，而不是等你动一下

> **一句话**：让它像扳手的不是能力不足，而是**触发、上下文、验收**这三件事仍然全压在人身上。项目已经为这三件各配了一个原语，默认用法一个都没用上。
>
> **读者**：互联网公司的开发、运维、数据工程师，以及把它用于个人事务的人。
> **前置**：[事件与任务](../events-and-tasks.md)、[智能体委派](../sub-agents.md)、[记忆](../memory.md)。

## 诊断

一次有价值的产出 = **触发 + 上下文 + 执行 + 验收**。

现在 AI 只接管了"执行"这一段。另外三段还在你手里，所以每一次产出都必须由你先动一下——这就是"扳手感"的全部来源。它不是模型能力问题，加大模型、调提示词都不会改变这个形状。

Pipiclaw 里对应的三个原语：

| 被压在人身上的环节 | 项目里对应的原语 | 常见的错误用法 |
|---|---|---|
| 触发 | 事件的 `preAction` 门控（零 token 传感器） | 写成"每天 9 点检查一下 XX"，让 LLM 自己判断有没有事 |
| 上下文 | channel 隔离的 memory / workspace / 台账 | 一个私聊什么都聊，记忆稀释到没用 |
| 验收 | task 的 DoD + 独立验收 attestation | 不写 DoD，产出仍然要你逐条重读 |

下面四条，是把这三个环节逐个交出去的具体做法。

---

## 1. 别让 LLM 判断"有没有事"，让 bash 判断

大多数人把周期事件写成"每天 9 点检查一下 XX"。这是最差的用法：agent 每天醒来一次、烧一次 token、九成时间告诉你"没事"。两周后你把它静音了——**被静音的自动化，产出是零。**

正确的形状是把它反过来：**cron 只是采样频率，`preAction` 才是真正的触发条件。**

写一段 5 行的 bash，没有事就 `exit 1`，LLM 根本不会启动，不消耗任何 token。带 `preAction` 的周期事件下限从 30 分钟放宽到 5 分钟，就是为这个用法开的口子（见 [events-and-tasks.md 的事件动作门控](../events-and-tasks.md#事件动作门控action-gate)）。

于是你的工作从"写提示词"变成"写传感器"——而传感器恰好是你本来就会写的东西：

- **运维**：告警队列里有没有超过 30 分钟未认领的 P2 → 有才叫醒它去关联最近变更、给出初判
- **开发**：`master` 的 CI 是否连续两次红；我名下的 PR 有没有超过 24h 没人动
- **数据**：昨天的分区行数是否偏离七日均值 20%；某张表今天有没有按时产出

```json
{
  "type": "periodic",
  "text": "刚检测到 master CI 连续两次失败。请拉取失败日志，定位是哪次提交引入的，给出初判和建议的处理方式。",
  "schedule": "*/10 * * * *",
  "preAction": {
    "type": "bash",
    "command": "~/.pipiclaw/workspace/skills/sensors/ci-red-twice.sh"
  }
}
```

再配合周期事件的 `[SILENT]` 规则：**只在有事时说话的机器人才会被信任，天天说话的会被静音。**

**推论**：值得投入的是一个 `sensors/` 目录，而不是一堆措辞更好的提示词。传感器可复用、可测试、可版本管理，而且写一次就永久生效。

## 2. 无人值守的唯一门票是"可机检的验收"

判断一件事能不能交给它长期跑，只有一个问题：

> **完成没完成，有没有一条命令能告诉我？**

- **有** → 做成 task：DoD 写成可执行的检查，开 `Independent verification: required`，让另一家模型做交叉验收（codex 验 claude 的活，或反过来）。attestation 绑定 `taskId`、contract body hash 和 artifact hash，DoD 改过或产物过期就不认（见 [Verification](../events-and-tasks.md#verification)）。这是你敢直接使用结果、而不必自己重读一遍的唯一理由。
- **没有** → 老实当扳手用，别自欺欺人做成自动的。没有验收的自治，只是把"自己干"换成了"自己复核"，省不下注意力。

**最有落地价值的推论：先写验收脚本，再建 task。**

花半小时写一个"这份周报的数字能不能被一条 SQL 复现"的校验，回报比花半小时调提示词高一个量级——前者把这件事**永久移出**你的注意力，后者只让这一次输出好看一点。

更进一步：你手上大量工作现在不可机检，往往不是本质不可检，而是从来没人给它写过检查。**把工作变成可检的，是 AI 时代工程师真正的新活。**

几个"看起来不可检、其实可检"的例子：

| 工作 | 看似的验收 | 可机检的 DoD |
|---|---|---|
| 周报 | "读起来对" | 每个数字能被记录在 Manual 里的一条查询复现 |
| 故障复盘 | "写清楚了" | 时间线上每个节点都有日志/监控链接；改进项都落成了 issue |
| 数据修数 | "跑完了" | 修复前后的一致性校验 SQL 返回 0 行差异 |
| 依赖升级 | "没坏" | 全量测试通过 + 关键接口 diff 为空 |

## 3. 唯一值得看的指标是"每周期人工介入次数"

大部分自动化的命运是随环境漂移而腐烂。这个项目里有一个东西可以反过来增值：task 文件的 `Manual` 段和 `History` 段，是你和它**共同编辑的手艺沉淀**。每跑完一个周期，它都知道上次卡在哪。

把它变成复利，需要三个动作：

1. 每次你被叫醒去人工介入，**不要只解决那一次**——顺手让它把这次介入的原因写进 `Manual`。
2. 建一个月度周期事件：
   ```text
   翻一遍活动任务的 History，找出本月介入次数最多的那一条，
   改写它的 Manual 或补一个检查脚本，让下个月不用再叫我。
   ```
3. 记录的指标不是"AI 帮我写了多少代码"，而是每条 task **这个月叫了我几次**。

一条上线时每周叫你 3 次的周报任务，两个月后应该是 0 次。**到 0 的那一刻，它才真正从扳手变成车床。**

配套的上线姿势——**棘轮式放权**：新任务先只读、只提议、不动手；提议连续正确若干周期后，再给它写权限。一次错误的自动动作损失的信任，要几十次正确才补得回来，而信任一旦没了，你就会退回到每次都盯着看，形状又变回扳手。

## 4. Channel 是"常驻责任"的边界，不是聊天窗口

memory、task 台账、workspace 全部按 channel 隔离，所以划分方式直接决定了记忆的信噪比。

常见错误是一个私聊什么都聊。正确的划法是**一个长期责任一个 channel**：你负责的那个服务一个群、那条数据链路一个群、on-call 一个群。

粒度不是"一个项目一个"，更不是"一次任务一个"，而是**会长期反复出现的责任**。理由很实在：

- recall 按 channel 召回，混着放的 `MEMORY.md` 会稀释到检索不出东西；
- task 台账混着放，每回合注入的 `<task_agenda>` 都在白烧上下文。

**推论：尽量用群，而不是私聊。** 把它放进团队真实在用的那个工作群——群里人类之间的对话，是它唯一能免费获得、而你永远不用手工提供的上下文。

跨 channel 需要共享的稳定背景（部署拓扑、命名约定、谁负责什么），写进 workspace 级的 `MEMORY.md` / `ENVIRONMENT.md`，不要在每个 channel 里重抄一遍。

## 一天的形状会变

四条合起来，你的角色从执行者变成**规格作者 + 验收人**：

- **早上**：写 2–3 份台账（Goal / DoD / Manual），派给外部 agent——一次跑几十分钟的活正是外部委派的场景——然后走开。
- **白天**：只被两种事叫醒——传感器认为出事了，或者验收没过。其余时间它在自己推进。
- **晚上**：看验收结果，把本次介入的原因回写 `Manual`。

最关键的心态转变：**不要在 agent 干活的时候盯着它。** 委派是异步 detached、完成后自动唤醒频道的；盯着看不会更快，只会把你自己重新变成瓶颈。反复轮询和重复派发是明确的反模式。

## 个人生活里的同一套原语

不用另学一套：

- **传感器不一定是监控系统**：今天有没有 commit、某个页面价格变了没、某个目录有没有新文件——一样是 `exit 0/1`。
- **最有价值的是闭环，而不是提醒**：一个每晚的 one-shot，让它翻今天的对话，找出"你说了要做、但没进任何台账的事"，逼出一条 task。人对自己的承诺，几乎都失效在没有台账这一步。
- 家庭、健康这类事的 DoD 常常就是一个数字或一张照片，**反倒比工作上的更好机检**。

## 反模式速查

| 反模式 | 为什么伤产出 | 换成 |
|---|---|---|
| "每天 9 点检查一下 XX" | 天天说话 → 被静音 → 产出归零 | `preAction` 传感器 + `[SILENT]` |
| 不写 DoD 就建 task | 结果仍需你逐条重读，没省注意力 | 先写验收脚本，再建 task |
| 反复 `/subagents` 轮询等结果 | 把自己变回瓶颈 | 委派后走开，等完成唤醒 |
| 一个私聊聊所有事 | 记忆稀释、上下文空烧 | 一个常驻责任一个 channel |
| 介入完就算完 | 下周期还会叫你 | 把介入原因回写 `Manual` |
| 第一天就给全自动写权限 | 一次错误动作烧掉信任 | 棘轮式放权：先只读只提议 |
