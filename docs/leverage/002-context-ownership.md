# 上下文的所有权：可写清 + 可机检 = 可委派

> **一句话**：[001](./001-from-wrench-to-lathe.md) 给了**出口**的判据——完成没完成，有没有一条命令能告诉我。这篇给**入口**的判据——开工需要的东西，我说不说得清。两个都成立，这件事才真的能交出去。
>
> **读者**：已经在用委派和任务台账，但感觉"教它还不如自己干"的人。
> **前置**：[记忆](../memory.md)、[Workspace Skills](../skills.md)、[智能体委派](../sub-agents.md)。

## 真正的成本不是 token，是转述带宽

外部委派会拉起一个真实的 Claude Code / Codex 进程，它从**零上下文**启动；内置角色跑在隔离上下文里，同样不继承你脑子里的任何东西。你脑子里那些"这不是显然的吗"——那台机器叫什么、这个字段其实早就废了、这个词在我们这儿是另一个意思——一句都不会自己过去。

所以当你觉得"让它干还不如我自己干"，多半不是模型笨，而是**你每一次都在重新口述同一批背景**。这部分工作没有任何复利：说十遍和说一遍一样贵。

**一个可执行的诊断**：翻最近 10 次委派的任务描述，数一数同一段背景你输入过几次。重复次数最高的那一条，就是你当下最该沉淀的一条。

> 001 给了产出侧的指标：**每周期人工介入次数**。
> 这篇给输入侧的对偶指标：**同一段背景的重述次数**。
> 两个都趋零，它才真的在替你干活，而不是在陪你干活。

## 放在哪一层，看的是"变化频率 × 复用次数"

载体各自装什么，[skills.md 的载体对照表](../skills.md#与其他知识载体的区别)已经讲清楚了，这里不重复。这里只给**选择轴**——同一条信息该往哪层放，取决于两件事：

| | 很少复用 | 反复复用 |
|---|---|---|
| **稳定** | 写进这次的任务描述 | 工作区级 `MEMORY.md` / `AGENTS.md` / skill |
| **常变** | 写进任务描述，用完即弃 | **别写文字，给它查询的命令**（见下节） |

放错层有两种对称的代价，都很贵：

- **放太高**（该在任务描述里的写进了工作区）：每一回合都在烧上下文，而且污染所有频道——这就是为什么频道隔离是默认值。
- **放太低**（该沉淀的留在你脑子里）：每次重述；更糟的是它**过期了也没人发现**，因为它从来没被写下来过，无从检查。

**一条实用规则**：判断该不该沉淀，问"这个月我还会不会再解释一遍"，不要问"这个重不重要"。重要但只说一次的事不值得沉淀，琐碎但每周都要说的事非沉淀不可。

## 记指针，不记快照

这是这篇最要紧的一条。

快照——"prod 集群是 `xxx-prod-01`"、"那张表大约 12 亿行"、"负责人是隔壁组"——都会过期。而且它们是**静默地**过期：不会报错，它会拿着一条旧事实，非常自信地把活干错。**这比忘记危险得多**，忘记至少会来问你。

指针不会腐烂：

| 别写（快照） | 改写成（指针） |
|---|---|
| prod 集群是 `xxx-prod-01` | 用 `<ctx 命令>` 列出当前集群，带 `prod` 标签的那个 |
| 这张表大约 12 亿行、按天分区 | 表结构和量级用这条 SQL 查：`...` |
| 服务 A 依赖服务 B 和 C | 依赖关系看 `<仓库路径>/deps.yaml`，以文件为准 |
| 发布窗口是每周四下午 | 发布窗口以 `<日历/审批系统>` 为准，用 `<命令>` 查 |
| 这个模块的入口在 `src/foo/bar.ts` | 入口用 `rg` 找 `<某个稳定的符号名>` |

推论很反直觉但很重要：**`ENVIRONMENT.md` 里最值得写的不是"环境是什么"，而是"怎么问出环境是什么"。**

一层含义是：**能被一条命令回答的事，就不要写进记忆。** 写进去只有两个结果——占用每回合的上下文，或者在某天悄悄骗它一次。真正值得写进记忆的，是命令问不出来的那部分：为什么当初这么定、哪条路走过并且失败了、哪个坑不要再踩。

## "写不清"有三种，处置完全不同

关键判断：**"写不清"是一个可以被投资消除的状态，不是这件活的固有属性。** 分清是哪一种，才知道该投什么。

**1）隐性知识——只在你脑子里，但本身是清楚的。**
处置：写下来，一次性成本。写进 skill 或 `ENVIRONMENT.md`，之后每次委派都免费复用。这是回报最高的一类，因为你付一次、它省无数次。

**2）目标本身模糊——连你自己也没想清要什么。**
处置：**这类活本来就不该委派。** 不管你怎么写提示词，让一个模型去执行一个你自己都没定义的目标，只会得到一份看起来完整、但方向不对的产出，而且你还要花时间读完才能发现。
正确的用法是把它当**思考对手**而不是执行者：用只读的内置角色，让它列出你没考虑到的选项、指出你的假设、追问你的口径。想清楚之后，它才回到第 1 类。

**3）上下文太大——要读半个仓库才能动手。**
处置：这不是"写清楚"的问题，写多少字都不够。这是**换执行者**的信号：外部 Claude Code / Codex 会自己探索代码库、自己读、自己迭代；内置角色不行。
这个判据比"重活给外部、轻活给内置"准得多——真正的分界不是活的大小，是**这件事需不需要执行者自己去建立上下文**。

## 一个被忽略的变化：文档的 ROI 已经不一样了

以前不写文档是**理性**的：读者是"未来可能来的新人"，可能根本不来；反馈周期以月计；写完就开始过期。投入产出比确实很差，所以团队普遍不写，这不是懒。

现在文档的读者变了——是**每一次委派**。一份 `ENVIRONMENT.md` 一个月可能被读几百次，写完当天就开始还本。同一份投入，回报周期从"以月计、也许没有"变成"以天计、确定发生"。

三条推论：

1. **值得写的东西变了。** 不是架构美文和设计理念，而是"怎么连上那个跳板机""这个指标的口径是什么""这个词在我们这儿指什么"——过去嫌太琐碎、不好意思写进文档的那些。它们恰恰是每次委派都要重述的东西。
2. **可以写得又丑又碎。** 读者是模型，不挑排版、不需要起承转合、不介意是一堆零散的条目。写文档最大的心理成本——"要写得像样"——在这里可以直接放弃。
3. **让它自己写。** 每次你口头解释完一段背景，顺手让它落到对应的层去。这和 001 里"把介入原因回写 `Manual`"是同一个动作的两侧：一个让**执行**变便宜，一个让**交待**变便宜。

## 合起来：什么能交出去

|  | **可机检**（出口清楚） | **不可机检** |
|---|---|---|
| **可写清**（入口清楚） | **无人值守**：做成 task，配 DoD 和独立验收，让它自己跑 | **可委派，但人来验收**：一次性委派就好，别做成周期 task |
| **写不清** | **先补上下文**：写 skill / `ENVIRONMENT.md`，或换成能自己探索的外部执行者，补完升到左上格 | **自己干**，或只把它当思考对手 |

大多数人卡在右下格，然后归因为"AI 还不行"。真实情况通常是：**这件事还没有被做成可交待、可验收的形状**——而把它做成那个形状，本身就是这个时代工程师最值钱的工作。

## 反模式速查

| 反模式 | 为什么伤产出 | 换成 |
|---|---|---|
| 每次委派都重述一遍同样的背景 | 说十遍和说一遍一样贵，没有复利 | 数重述次数，最高的那条先沉淀 |
| 把"以后可能有用"的都写进工作区记忆 | 每回合烧上下文、污染所有频道 | 按"变化频率 × 复用次数"选层 |
| 把环境事实当快照写进记忆 | 静默过期，它会自信地拿旧事实干错活 | 记指针：写查询的命令，不写答案 |
| 目标没想清就派出去 | 得到一份完整但方向错的产出，还得读完才发现 | 先用只读角色当思考对手，想清再派 |
| 上下文太大就拼命写更长的任务描述 | 写多少字都不够 | 换外部执行者，让它自己建立上下文 |
| "等有空再补文档" | 按旧 ROI 判断，而旧 ROI 已经不成立了 | 每解释一次，就让它顺手落盘 |
