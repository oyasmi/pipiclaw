# 让 token 持续转化为可验收的产出

> **读者**：已使用任务与委派，希望减少重复解释、无效返工和人工追赶的人。
> **前置**：[事件与任务](../events-and-tasks.md)、[智能体委派](../sub-agents.md)、[记忆](../memory.md)。

算力只有在推进用户需要的结果时才产生价值。有效交付同时满足三个条件：目标成立、证据充分、符合适用的工作要求。`done`、PASS、代码行数和工具调用次数都不能单独替代它。

本文保留工作方法；早期审查的问题清单、修复实施进度和一次性复现已清理。当前机制与参数以顶层指南为准。

## 看整个交付的成本

每周抽样同类工作，关注四组指标：

| 指标 | 怎样记录 | 防止误读 |
|---|---|---|
| 有效交付率 | 验收并交付后，没有因遗漏要求而返工的比例 | 运行时关闭不等于用户认可 |
| 人工介入 | 必要决策、补上下文、纠错的次数与耗时 | 少问但做错不能算改善 |
| 总成本 | 主 agent、执行、验收、失败尝试与记忆维护的费用 | 实报、估算和未知分开，不只统计成功 run |
| 交付时间 | 同类工作的中位数与较慢案例 | 区分有效执行、等待与停滞 |

再问一个问题：**同一条要求，这个月是否被重复解释或纠正？** 这比“存了多少条记忆”更能说明记忆是否产生了作用。

## 一份稳定契约，加一份本轮工作单

任务契约保存跨轮不能丢的目标、DoD、Manual 和验收要求。本轮委派描述选择执行者此刻需要的材料，直接放进现有 `subagent` 的 `task` 参数：

- 要交付的结果及其最终位置。
- 已确认的范围、约束、用户偏好和不应变更的内容。
- 当前代码、失败实验、已有有效改动和真实证据的位置。
- 要完成的检查、通过条件与停止条件。
- 返回哪些结果，哪些仍未验证。

不同轮次需要不同材料：

| 轮次 | 重点材料 |
|---|---|
| 首次实现 | 目标、范围、接口、适用要求与验收方法 |
| 失败后续修 | 具体失败、证据、违反标准、已通过项与修复边界 |
| 换执行者 | 已有改动、已排除假设、未解决问题与恢复入口 |
| 最终验收 | 最终交付位置、完整 DoD/Verification 与证据要求 |

给路径前先确认该执行者能访问。外部 CLI 不继承主对话；内置执行者的背景注入也不能代替本轮工作单。已有产物用可读指针取回，避免每轮复制整份日志。

## 让偏好成为可检查的要求

记忆中的偏好需要转译成当前任务的约束。例如“少引入依赖”在一次实现中意味着：新增依赖须解释必要性，并由验收者检查它是否服务于本次目标。

先判断作用域和冲突：当前明确要求优先，项目例外只在对应范围生效，不把一个频道的内容自动升格为共享背景。用户没反对、审查者提过一次、模型再次读到自己的旧总结，都不能当作新确认。

任务教训先留循环日志；确实影响后续实施时，在最终验收前更新 Manual。PASS 之后修改契约可能要求重验。多次验证有效且跨任务复用的方法才适合沉淀为 skill；不能假设静默任务关闭后所有经验都会自动进入频道记忆。

## 先裁决反馈，再返工

将反馈分成三类：违反 DoD 或明确约束的必修问题、有证据但仍需区分的疑点、任务外增强或风格建议。只有第一类必然触发返工；第二类先做窄范围调查；第三类不自动扩大本轮范围。

返工指令按“现象 → 证据 → 违反标准 → 修复边界与已通过项 → 重验办法”组织。同一问题反复失败而没有新证据时，改变调查方法或执行者；不能只重复相同指令。

正式验收应覆盖最终交付，包括代码、文档、测试和收尾改动。关闭门禁的现行规则见[独立验收](../events-and-tasks.md#独立验收)；门禁证明的范围与验收者的证据强度仍需分清。

## 用对照证明改善

机制问题用 unit/e2e 验证副作用；模型是否更会应用要求、选择执行者和完成工作，用[行为评测](../evals.md)或代表性真实任务验证。

先比较一种变化，固定模型、角色、工具权限、仓库状态和目标范围。保存失败轨迹与全部成本，保留不用于调 prompt 的任务。少量 trial 可以发现明显问题，不能当作成功率的统计证明。

如果工作单和指导材料已经解决问题，就停在这里。新增学习入口、上下文诊断或自动路由，应以多个真实失败样本为依据，并复用现有 task、run、reflect 和 artifacts。新增机制的维护成本也属于总成本。
