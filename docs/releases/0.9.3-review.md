## 关键决策与证据

- 按实际迁移实现收敛支持范围：v3（`status:` 且无 `state:`）自动转换；带 `state:` 的 v4 beta 原样跳过，须隔离后人工重建，不承诺 v4 自动升级。证据：`src/runtime/task-migration.ts` 的 `parseV3Frontmatter` / `convertOneTask`；`test/task-migration.test.ts` 的原件逐字节保留用例。未新增 v4 转换机制。
- 修正 design D12、实施顺序与实施记录，统一 `.v3/` 备份目录；保留旧数据、记录和未解决清单。（已被第二轮返工取代：失败现在回滚、不写 marker、中止启动。）不推荐删字段或手写 ticket。证据：`docs/events-and-tasks.md` 的“beta 用户升级与不可转换任务”。
- v4 旧字段可能被普通读取忽略，旧票可能归一化为 open；doctor 不能证明识别全部 v4。证据：`src/tasks/frontmatter.ts` 的 `LEGACY_KEYS` / `parseTaskFrontmatter` / `normalizeTaskFrontmatter`。已修正 doctor 的字段列表及“重启即可升级”的误导性指引。
- 【补充修复】严格迁移发现不能仅靠目录名恢复含 `/` 的群频道 ID；缺少/损坏 `CHANNELS.md` 时把 `group_...__...` 当作真实 ID 会令周期模板指向错误频道。现 strict discovery 对未索引的转义频道目录失败并要求恢复频道索引，不写 marker；常规后台发现仍保持宽松。新增 `test/channel-index.test.ts` 与 `test/task-migration-faults.test.ts` 回归用例。
- 【返工修复】v3 停用（`enabled: false` / `control.stop`）的周期任务曾仍会生成无停用标志的事件模板，与“升级不会让已停用任务重新跑起来”矛盾。现 `convertOneTask` 先判定 `stopped`，停用任务不调用 `writeTemplateEvent`：任务转 `paused`、不设 `origin`、不归档（含 `sleeping`），循环日志 note 记录原周期，原件在 `tasks/.v3/`。证据：`src/runtime/task-migration.ts`；新增回归 `test/task-migration.test.ts`“never turns a stopped recurring task into a runnable event template”（enabled=false、control.stop、sleeping+enabled=false 三例：paused、无事件文件、无 events 目录、备份存在、note 含 cron）。
- 【返工修复】原升级步骤要求“生产首次启动前隔离生成的模板”不可执行：迁移在 bootstrap 内完成后 watcher 立即启动，且没有独立转换命令。文档改为：在副本盘点将生成的模板；停 daemon 时对不应周期运行的原 v3 任务先设 `enabled: false`（先备份）；首次启动前移出可能冲突的既存同名/关联事件；无法确定则停在备份阶段。未承诺任何未实现工具。
- 【返工2】(1) 停用任务 `control.stop` 缺 reason/空白时曾因 paused 被 frontmatter 丢弃而恢复为可运行：现 `stopped` 独立于 reason，缺省原因“v3 中已停用。”。(2) 转换失败不再写 marker 并继续启动：单任务回滚（恢复原件、删模板/归档/新日志），写 `state/task-migration-v5.failed.json`（阶段+回滚结果），迁移抛错、bootstrap 不再吞掉，watcher/driver/钉钉不启动；回滚失败的报告持续阻止启动。(3) `.v3/` 备份改为 `COPYFILE_EXCL`，已有不同备份保留、新副本存 `<id>.backup-<n>.md`。(4) 新增 `scripts/rehearse-task-migration.mjs`（只读复制 tasks/events 到临时目录，直接调用迁移函数，不经 bootstrap）。测试：`test/task-migration.test.ts` 新增缺失/空白 reason、备份不覆盖、archive/template/backup 阶段故障与回滚、重试清除报告、回滚失败阻塞。回滚不清理转换前已存在的文件；回滚后若进程在中途被杀，则无回滚，依赖 `.v3/` 备份人工恢复。
- 仍存在的边界：启用的 v3 周期任务（含 `sleeping`）迁移后会生成启用的模板，启动后无法拦截；手工设 `enabled: false` 依赖操作者先识别，且会改变原文件（有备份）。未验证：真实 watcher 调度行为、真实用户任务，以及“设 `enabled: false` 后在真实频道迁移”的端到端流程；上述 CI/e2e 事实未变。
- README 中 driver 的周期调度描述改为事件模板每次生成独立实例；补齐双语 changelog 与发布草稿。

## 返工复核补充记录

- 【返工3】独立复核 run_j4wf2j 确认四项缺陷，已修复：(1) 任务/事件目录 `readdir` 仅 ENOENT/ENOTDIR 视为空，其他错误记为 `scan`/`events` 失败、不写 marker；(2) task-owned 事件备份由 `rename` 改为不覆盖的复制（同名异内容存 `.backup-<n>.json`）后删除原文件；(3) `archiveTask`（`src/tasks/store.ts`）遇既有归档条目拒绝覆盖，中途失败撤销已移动日志与归档契约，迁移回滚不再删除/覆盖既有归档；(4) 归档日志 rename 错误不再被吞，向上抛出使迁移失败。这些**取代**此前“回滚总是 ok、归档会覆盖”的表述：现在回滚结果中的 `ok` 仅在上述撤销全部成功时成立，撤销失败会在错误中注明 `undo of partial archive failed`。证据：新增 `test/task-migration-faults.test.ts`（真实临时目录，对 `readdir`/`rename`/`rm` 做定向故障注入，覆盖四项及 `archiveTask` 回退）与 `test/task-migration.test.ts` 的事件备份不覆盖用例。限制：故障由 `vi.mock("node:fs/promises")` 注入而非真实权限错误（本环境无法可靠制造 EACCES）；`archiveTask` 的撤销本身失败、进程中途被杀仍无法自动恢复，依赖 `.v3/` 备份与人工核对；`archiveTask` 行为变更也影响 `task_close`（遇既有归档会报错而不是覆盖），未做真实 daemon 端到端验证。
- 【返工4】W2 独立验收确认两条 P1，已修复：(1) 频道发现失败不再被当作“没有频道”：`discoverWorkspaceChannelIds`/`discoverTaskChannels` 新增 `strict` 选项（仅迁移使用），`CHANNELS.md` 或 workspace 根 `readdir` 出现 ENOENT/ENOTDIR 以外的错误时抛出；迁移记为 `stage: "discover"` 失败，写失败报告、不写 marker、抛错，修复后重试仍会处理任务。后台 worker 的宽松行为不变。(2) `archiveTask` 撤销本身失败时抛出 `ArchiveUndoError`（含滞留在归档路径的文件清单）；迁移不再清理归档侧文件和日志（此前会删掉尚未搬回的旧日志），回滚结果记为 `rollback failed, archive undo incomplete: …`，该报告持续阻止启动，需人工把清单中的文件搬回后删除报告。**修正前文结论**：【返工3】中“归档撤销失败时回滚仍为 ok / 迁移回滚会清理归档文件”的含义已作废；回滚 `ok` 现在只在 `archiveTask` 自行撤销成功时出现，迁移从不 unlink 归档侧文件。证据：`test/task-migration-faults.test.ts` 新增两条回归（真实临时目录 + 定向 `readdir`/`rename` 注入）。限制：仍是 mock 注入而非真实权限错误；撤销失败后的人工搬回与进程中途被杀仍无自动恢复。
- 【返工5】W2 独立审查发现 P1：恢复失败报告读取异常被吞成 `{}`，损坏/异常结构的报告被当成无失败，随后被删除并写成功 marker。已修复（`src/runtime/task-migration.ts`）：报告不存在 = 首次启动；报告存在但读取失败（如 EACCES）、JSON 无法解析、或结构不合规（`failures` 须为非空数组，每项 `channelId`/`stage`/`error`/`rollback` 为字符串、`task` 可选字符串）一律抛出 `blocked` 错误，保留报告、不写 marker、不启动服务。因此“持续阻止启动”的前提是：报告存在，且（含失败回滚 / 不可读 / 不可解析 / 结构不合规）；仅当报告结构合规且所有 `rollback` 均为 `ok` 时才重试，成功后删除报告并写 marker。已生成的有效报告（写入端始终产出非空、字段齐全的 failures）保持兼容。人工处理：检查报告并恢复原件后手动删除报告。证据：`test/task-migration-faults.test.ts` 新增参数化回归（损坏 JSON、非对象、缺字段/错类型等）与 `readFile` EACCES 注入，并保留有效报告重试用例。限制：EACCES 仍为注入模拟；读取与 existsSync 之间的竞态按“读取失败”阻断。
