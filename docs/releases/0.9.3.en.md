# 0.9.3 release notes (draft, unreleased)

Pipiclaw now leads one-off task projects through goals, done criteria, and work items. Each task has its own session, a team board showing delegation results, and durable dispatch/settle evidence in its loop log. A checker's `VERDICT` informs the leader's decision; completion still requires checked DoD items and no in-flight work.

Scheduled and recurring work uses event task templates: each occurrence creates an independent instance, with a receipt when an active instance causes a trigger to be skipped. Wait tickets are `time` / `work` / `ask`; project budgets cover steps and attributable costs. Chat receives explicit task reports and runtime receipts.

This release also collects the 0.9.3 beta series' tool guards, memory reflection, delivery reliability, eval tooling, and capability/cost-based agent examples. See the [changelog](../../CHANGELOG.md) for details.

## Upgrade before resuming work

Automatic conversion supports v3 only (`status:` without `state:`), preserving originals under `tasks/.v3/`. **v4 beta tasks are skipped and require isolation of originals and related events, followed by manual rebuilding through v5 tools.** Do not merely remove old fields, write tickets directly, or delete the migration marker to rerun conversion. Reconcile old usage, budgets, external waits, and completed external actions; keep unresolved items on a recovery list.

Settle external runs first, stop the daemon, and back up the entire app home. Rehearse with `node scripts/rehearse-task-migration.mjs` (after `npm run build`; it copies tasks/events read-only to a temp dir and calls the migration function directly, starting no services) and verify each task/event before enabling it. Disabled v3 recurring tasks stay paused and get no event template. Other recurring tasks do generate live templates and the watcher starts right after migration, so they cannot be intercepted afterwards: inventory them on the rehearsal copy and handle the original tasks while the daemon is stopped. Recurring tasks that cannot be expressed as templates pause with a note. A conversion error rolls that task back, writes no marker, records `state/task-migration-v5.failed.json`, and aborts startup (no watcher/driver/DingTalk) until fixed; a restart then retries. Follow the [upgrade procedure](../events-and-tasks.md#beta-用户升级与不可转换任务).
