# 0.9.3 发布说明（草稿，未发布）

Pipiclaw 现在以负责人模式推进一次性任务：目标、验收清单与工作项保存在契约中，独立任务会话通过团队看板读取委派结果，并在循环日志保留派发和结算证据。检查者的 `VERDICT` 供负责人裁决，完成时仍须确认 DoD 且无在途工作。

周期与定时工作交给事件任务模板，每次触发生成一个独立实例，同一模板有活动实例时跳过并回执。等待统一为 `time` / `work` / `ask`，预算覆盖整个项目的步数与可归因成本；聊天接收明确的 `report` 与运行时回执。

本版也汇集 0.9.3 beta 系列的工具守卫、记忆反思、投递可靠性、eval 框架与能力/成本档位委派示例更新，详细列表见 [CHANGELOG](../../CHANGELOG.zh-CN.md)。

## 升级必读

自动转换仅支持 v3（`status:` 且无 `state:`），原件保留在 `tasks/.v3/`。**v4 beta 任务不会自动转换，须先隔离原件与关联事件，再通过 v5 工具人工重建。** 不要只删旧字段、手写等待票或删除迁移标记重跑。旧用量、预算、外部等待和已执行的真实动作必须核对，未解决项保留清单，不得丢弃。

先处理在途外部 run，停止 daemon 并备份整个 app home；在隔离副本演练后逐项验收。停用的 v3 周期任务保持暂停且不生成事件模板；其余周期任务会生成启用的模板，且迁移后 watcher 立即启动，无法事后拦截，须在副本盘点后、停 daemon 时先处理原任务。模板不可表达的周期任务暂停并记录原因；转换出错时回滚该任务、不写标记、启动中止，详见升级指南“失败处置”。演练用 `node scripts/rehearse-task-migration.mjs`（先 build，只读副本、不启动服务）。执行步骤见[升级指南](../events-and-tasks.md#beta-用户升级与不可转换任务)。
