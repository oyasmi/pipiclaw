# 默认个人助手：把 dot 变成按需使用的隔离能力

日期：2026-10-23。承接 058，调整初始化、首次绑定和旧布局迁移约定。

> 后续决策见 [060 Desk](../060-desk/design.md)：一个助手、多个工位，目录改为 `workspace/desk-<name>/`。本篇保留默认接入实施记录；下文的迁移脚本方案已退役，改用[一次性迁移说明](../../desk-migration.md)。060 的运行时重构已实施，见其[验收记录](../060-desk/acceptance.md)。

## 判断与边界

Pipiclaw 的普通使用路径是同一个个人助手出现在私聊、多个群和终端里。058 将渠道与助手本体解耦是正确的，但把“先创建 dot、再逐群绑定”作为必经步骤，把内部模型暴露成了安装门槛。应保留 dot 的所有权边界，把默认选择交给安装和入站机制。

共享人格、长期记忆和工作文件不意味着把所有群消息拼成同一条会话。每个渠道继续有独立的 session、上下文和回复地址；任务、事件和委派的完成通知继续回到它们原来的投递渠道。不同群能访问同一个助手的长期积累，不能用会话独立来承诺资料隔离。确有隔离需求时创建其他 dot。

这次不增加人格选择配置、默认 dot 切换开关、运行时合并命令或新的权限体系。发送者准入仍使用现有 allowFrom。

## 初始化与目录

`bootstrapAppHome` 首次执行即初始化 `workspace/dots/default/dot.json`，包括只生成配置模板后退出的首次运行。直接嵌入 daemon 的 `createRuntimeContext` 也执行相同初始化。其他 dot 仍显式创建。

默认助手与其他 dot 使用完全相同的布局：

```text
workspace/
├── SOUL.md / AGENTS.md / ENVIRONMENT.md  # 共享身份、规则与环境
├── MEMORY.md                           # 人工维护的跨 dot 背景
├── CHANNELS.md                         # 生成的渠道索引
├── skills/ / sub-agents/                # 共享能力与角色
└── dots/
    ├── bindings.json                   # 所有已接入渠道的实际绑定
    └── default/                        # 默认助手的 cwd，其他 dot 同构
        ├── dot.json
        ├── memory/ / MEMORY.md / journal/
        ├── tasks/ / events/ / subagent-artifacts/
        └── conversations/dm-1/ … group-1/ … tui-1/
```

业务目录按需生成，不在安装时堆空目录。默认助手不放在 workspace 根目录，不用软链接或根目录别名：这样无需让每项工具、记忆、任务、备份逻辑都识别两种布局，后续增加隔离空间也无需迁移默认助手。共享配置保留在根目录，dot 的自主记忆始终只有 memory/ 这一事实源，根 MEMORY.md 不改为运行时写入。

初始化可重复执行。新 dot 在临时目录中写完整记录后原子发布，避免 daemon 与 TUI 同时首次启动时读到半成品。已有目录即使记录损坏也不修补；绑定表已经引用却目录丢失的 default 不重建。旧布局或迁移中断状态不创建 default，以免妨碍迁移或掩盖数据丢失。

## 首次接入

获准的真实钉钉消息，在附件保存和命令分流前执行 `ensureDefaultBinding`。只有不存在绑定时才分配 default 会话并提交 bindings.json，随后激活后台服务。复用原有绑定事务和串行写队列，并在队列内重查是否已有绑定，防止同时进入的新群消息丢失更新或覆盖显式绑定。

真实生产入站和直接 routeInboundEvent 入口都覆盖该步骤。重复调用不写盘。初始化和绑定不是模型决策；不需要模型先创建 dot 或向用户解释 dot。

以下路径不自动绑定：只读 resolve、状态查询内部读取、任务/事件/委派合成唤醒、后台通知。否则历史工作可能凭一次投递重新接通一个已经离开的渠道。原有跨 dot 投递校验保持不变。

终端省略 --dot 时固定打开 default；多个 dot 存在时也不猜测。显式 --dot 不存在时仍需 --create。创建第二个 dot 不改变普通终端入口。

## 升级与迁移

已有 dot 布局只补建缺少的 default，所有已有绑定保留；不自动合并既有助手的记忆和任务，也不擅自改名已有 dot。

旧按渠道目录布局仍离线迁移。脚本不带 --map 时将所有旧渠道汇入 default，按种类递增分配会话区。--map 是保留隔离的覆盖项，--drop 保留为归档选择；默认备份、dry-run、停机检查、后台进程检查和中断标记保持。

合并以保全数据为优先：预检检查业务文件、任务、委派、作业和派发 id 的目标冲突，任何重名叶子都在备份和写入前拒绝，不自动覆盖、改 id 或判断哪条记忆正确。处理冲突后可重试，也可将冲突源映射到独立 dot。同日 journal、审计日志或遗忘记录重名同样拒绝：它们具有顺序和来源语义，不能随意拼接。各渠道生成的旧 MEMORY.md 索引归档；memory/ 事实文件不变，统一索引由正常记忆更新重建。模型回忆从事实文件读取，不依赖旧索引。

显式映射全部旧渠道到其他 dot 时仍创建空 default，为新渠道提供稳定默认入口。迁移记录允许同一 dot 有多个来源，verify 同时理解旧单来源记录。脚本只修改用户指定的迁移副本或 app home；本次开发不执行真实 home 迁移。
