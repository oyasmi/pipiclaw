# 057：不依赖人工复核的行为评测闭环

状态：已完成。日期：2026-10-14。承接 056；用户明确要求去掉人工参与并授权约七小时的自主改进和真实模型实验。保留原始证据，不把模型共识冒充真值，不增加生产 runtime 的写入或自动发布权限。

## 目标与边界

一次命令应自动给出可信范围内的结论：评分器是否通过正反例校验、Agent 是否完成目标、失败来自哪一层、与可比参照有何差异。没有足够证据时输出不可判定；不得因为没有人标注就永远 pending，也不得为得到绿色分数放宽目标。

本轮顺序：离线评分器资格验证 → 修正会制造假失败/假通过的判定 → 固定实验条件 → 真实 core 采样 → 自动归因与兼容参照 → 形成可重复运行入口。人工标注、人工复核、由人批准晋升不在日常路径中。

## 初步审查依据

- 12 个核心场景目前全部使用代码 oracle；四处模型 grader 中两处属于退役场景。无需用另一批 LLM 替代人工来决定核心是否通过。
- 既有正反例只存在于测试，日常付费 run 不会检查 oracle 资格，也没有资格结果随实验冻结。
- 编码 oracle 信任试验目录中的 evaluator，且只检查退出码；候选实现提前 exit(0) 或改弱公开测试仍可能伪装通过。验证行为只看任意 bash 调用也不足以证明验证真的执行。
- 部分任务/记忆 oracle 固定工具名、字段顺序或文案，可能拒绝等价完成；反之，缺少相关工具结果、使用较早的正确答复掩盖后来错误等情况可能通过。
- fixtureSeeds 已记录但多数场景没有使用；相同场景多次试验仍是相同固定值，不能抵抗记住答案或偶然模板匹配。
- 报告中的人工队列与 pending 校准和用户新要求不符。主结果必须由能自动校验的证据决定，主观模型点评只能作为附注。

## 设计原则

1. **客观验收优先。** 使用实际文件、独立执行结果、持久化运行状态、相关联的成功工具结果、按步骤隔离的最终交付。模型评分不拥有否决客观成功或放行客观失败的权力。
2. **评分器也要被测。** 声明已知正确样本、已知错误反例、应当保持结果不变的等价变换。真实 run 前自动执行，结果和 case/oracle 指纹一起冻结。资格不完整的场景可以探索，但不能支撑自动基线结论。
3. **失败保留。** 自动复现是新试验，不能抹掉首次失败，也不把重试成功当作原试验成功。评分器修复走追加重评，不能覆盖旧 grade。
4. **可判定范围透明。** 正反例通过仅说明检测到声明的错误类型，不代表评分器普遍正确；未覆盖项、主观项、执行/证据问题明确列出，不伪造 certainty。
5. **实测闭环。** 自动流程有清楚的资源与时间上界，冻结模型、thinking、工具、case、oracle、seed、trial 和并发。参照不兼容时不计算差值；不把后改的 oracle 伪装成 runtime 改善。
6. **小而可维护。** 复用现有证据重放和核心测试，优先替换脆弱判定与低价值断言；不为了无人化再堆一套大型平台。

## 最终接口与约束

`selftest` 不调用模型；`run` 强制校验评分器资格；`cycle` 将执行、诊断、封存证据重放、严格参照选择和报告连成一次有限流程。oracle 控制、judge policy 和 seed 纳入冻结计划。控制失败阻止模型调用；控制未覆盖则仅作探索，禁止自动参照。

主判定只使用客观 grader。模型点评默认关闭，显式启用后为 advisory；禁用不产生“未知点评费用”。历史人工标注保留为历史数据，不进入新周期的批准路径。

自动参照只在完整 required 计划满足冻结 gate、资格有效、全部结果可用且证据重放一致时建立。已有兼容参照保持不动，失败不自动重试成绿；case/oracle/控制、seed、样本、预算、实际配置、实验变量任一不兼容即不显示差值。新自动产物位于 gitignored results 下，防止参照生成改变下一轮源码指纹。

周期开始前累加所有 trial 的时间和主体费用预算；默认接受 $25 / 180 串行分钟的保守包络，超出即在模型调用前拒绝。实际耗时通常低于包络；已记录费用阈值不是服务商账单硬限额，在途响应和未知外部费用始终明确说明。周期不追加样本、不自动修改产品或放宽判定。

验收、变异保护、实测与限制见 [验收记录](acceptance.md)。

运行条件补充：编译代码、playbook、fixture 和 lockfile 的执行指纹在开始、启动后续 worker 前和结束时复查。中途构建或修改执行输入会使本轮不可判定，不能把混合版本结果自动建立为参照；增设一项本地 provider hold/release 机制测试并实际打坏防线验证。
