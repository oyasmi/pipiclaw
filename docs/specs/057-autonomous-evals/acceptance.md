# 057 验收与实验记录

日期：2026-10-15。范围为评测工具、场景、评分器和文档；生产 `src/` 无改动。用户要求去掉人工参与后，以自动控制样本和客观证据代替人工标注、复核与逐次基线批准。

## 已落地的闭环

- `cycle` 自动检查计划包络、校验 oracle、执行真实模型、定位失败、验证并重放封存证据、选择兼容参照并生成短报告。
- 每次付费 `run` 同样强制执行资格检查。控制失败在准备模型环境前停止；缺少控制的扩展场景为不可判定，不会建立自动参照。
- 核心 12 场景具有 75 个控制样本；连同路径、研究、任务记录共 15 场景、90 个控制（40 个有效/等价样本，50 个错误样本）。全部离线通过，模型请求为 0。证据：`evals/results/qualification-release-057/oracle-checks.json`。
- 主观 judge 默认关闭，只在显式 `--judge advisory` 时调用，独立计费；客观结论不依赖模型共识或人工标签。旧标注仅作为历史资料保留。
- 自动参照位于忽略的 `evals/results/references/`；选择时检查封存哈希、完整样本、资格、重放、实际配置和实验变量。生成结果不会污染源码指纹；不兼容、不完整或损坏的参照明确拒绝。
- 固定 seed 驱动关键事实，异步生产者由 fixture 明确释放。代码验收不执行模型可修改的 evaluator；指定步骤的真实交付、相关联的成功工具结果和持久化执行记录支撑判定。
- 阶段目标使用明确的 JSON 决策字段，检查未来证据开放前不能先写最终结果。等价 JSON 排序、直接持久记忆读取、shell 写文件等不会因固定工具名或格式被拒绝。
- 保留所有原始失败；新运行、重评和证据重放都不覆盖原始 grade。SDK 漏报 token 合计而分项已知时，合计从分项推导并标注，原始资源账本不变。

## 结论边界

已实现无人参与的**评测执行与判定**，不会在周期内自行修改产品、放宽 gate、发布或发送外部消息。没有新建部署者的定时任务；`cycle` 可直接接入已有定时器/凭据环境，按退出码完成，无交互等待。

90 个控制只证明能分辨声明的有效解法和错误类型，不保证通用自然语言评分正确。当前可靠覆盖是 15 个场景；未覆盖的历史/扩展场景继续明确输出不可判定。每场景 3 次用于回归信号；即使全部通过，也不能据此声明模型总体可靠或统计显著提升。
