# 063 — 共享技能目录

状态：已实施，验证通过。日期：2026-10-27。

## 1. 需求与范围

Pipiclaw 同时从以下目录加载技能：

| 来源 | 目录 | 优先级 |
|---|---|---|
| 工作区 | `$PIPICLAW_HOME/workspace/skills/` | 高 |
| 用户共享 | `~/.agents/skills/` | 低 |

同名的有效技能使用工作区版本。提示词中的技能目录、`/skill:名称`、`/skills` 和模型的 `skill list/read` 采用相同的发现、过滤和名称解析规则。

本次只完成双来源的正式支持和必要的一致性修正。不增加配置开关、任意搜索路径、安装器、文件监听、跨会话刷新服务或完整的格式规范校验器；不改变内部及外部委派执行器的技能加载方式。

[Agent Skills specification](https://agentskills.io/specification) 定义技能文件格式和按需加载方式；`~/.agents/skills/` 在本设计中是 Pipiclaw 明确支持的发现路径，目录优先级由 Pipiclaw 决定。

## 2. 当前实现与问题

- `src/skills/loader.ts` 显式加载工作区技能并扫描内容。`src/agent/session/session-host.ts` 再将其与 pi ResourceLoader 的 `base` 技能合并，有效工作区技能覆盖同名 `base` 技能。
- 当前依赖的 pi 1.2.0 已通过包资源发现机制加载 `~/.agents/skills/`。Pipiclaw 保留 `base`，所以已经间接支持共享技能，但这些技能没有经过 Pipiclaw 的内容扫描，最终来源范围也依赖 SDK 的默认发现行为。
- `src/skills/workspace.ts` 为 `/skills` 和 `skill` 工具另外扫描一级工作区目录，并按目录名拼接读取路径。它看不到共享技能，也与 pi 已支持的递归发现范围不一致。
- `/skills list` 当前采用默认安全配置，`/skills show` 则加载实际安全配置，可能列出实际配置禁止读取的技能。

因此不能只向现有 loader 再加一次共享目录扫描；需要让 Pipiclaw 决定最终目录，并让管理入口复用它的解析规则。

## 3. 加载与覆盖规则

### 3.1 路径和发现

共享目录默认通过 `node:os` 的 `homedir()` 解析，与 app home、desk 和进程 cwd 无关。它指运行 Pipiclaw 的服务器账号的主目录；容器或服务部署需要在该账号可见的位置提供技能。

两个来源都沿用当前工作区使用的 SDK 目录发现规则：递归查找 `SKILL.md`，遇到技能根目录后不再继续向下寻找其他技能，并保留现有根级 Markdown 技能、忽略文件及符号链接处理。普通参考 Markdown 不因位于技能目录中就自动成为技能。不新增“共享目录只允许一级子目录”的限制。

目录不存在视为空，不自动创建共享目录。权限或读取故障保留带路径的诊断，不能伪装成正常空目录；单个来源或文件失败不应阻止另一来源的有效技能加载。

生产代码使用固定的两个来源，内部加载参数允许显式传入共享目录以便隔离测试；不把该参数做成用户配置。

### 3.2 有效性和合并

先分别加载、过滤，再按名称合并。这里的“有效”指 SDK 成功解析并返回，且通过 Pipiclaw 现有内容扫描和实际读取路径规则的技能，不表示通过新增的完整规范校验。

| 工作区版本 | 共享版本 | 最终结果 |
|---|---|---|
| 有效 | 不存在 | 工作区版本 |
| 不存在 | 有效 | 共享版本 |
| 有效 | 有效且同名 | 工作区版本；记录共享版本被覆盖 |
| 加载失败 | 有效且同名 | 共享版本；同时保留工作区失败诊断 |
| 有效 | 加载失败 | 工作区版本；同时保留共享失败诊断 |
| 均无有效版本 | — | 不提供该技能；保留可报告的失败原因 |

空目录、缺少技能文件或加载失败的候选项不占用名称。技能名称使用 SDK 解析得到的名称，按精确字符串比较，不增加大小写归一化或来源前缀。

同一来源内的重名候选按发现路径的稳定排序取第一个有效版本，其余记录冲突；不能依赖文件系统枚举顺序。相同名称且实际为同一文件时只保留一个，来源标记优先为工作区，不报告虚假的跨来源冲突。

合并结果保留胜出技能的实际文件路径、引用根目录和 SDK 元数据，包括 `disableModelInvocation`。该字段仍按 SDK 原有规则决定是否出现在自动调用目录中，不把“仅显式调用”误报为加载失败。

### 3.3 格式处理

复用 SDK 的解析和诊断，不再用列表入口的逐行正则另行解释 frontmatter。若诊断展示需要读取 frontmatter，复用 SDK 已导出的 `parseFrontmatter`，确保多行 `description` 与加载器一致。

本次不将 SDK 原本允许加载的格式 warning 全部升级为拒绝，不新增空正文、可选字段、名称长度等校验政策。列表不能仅因存在 warning 就把成功加载的技能标为失败。现有内容扫描规则保留并应用于两个来源；读取或扫描失败的文件从本次有效目录排除并给出诊断。

`allowed-tools` 等元数据不会授予额外权限。技能正文和引用内容按需读取，不把所有技能正文注入系统提示。

## 4. 最小实现结构

实现仍归属 `src/skills/`，不增加新的架构层或持久状态。

| 位置 | 调整 |
|---|---|
| `skills/loader.ts` | 显式加载两个来源，执行共同过滤、稳定去重和覆盖，返回有效技能与诊断 |
| `skills/types.ts` | 仅放本模块共享的来源、目录条目及加载选项类型；若无需独立类型则不新增文件 |
| `skills/workspace.ts` | 将工作区专用的列表和名称拼路径逻辑改为基于共同加载结果的目录访问；按职责改名，更新调用方，不保留重导出兼容层 |
| `skills/validation.ts` | 保留内容扫描；清理被共同解析取代的重复 frontmatter 解析及仅供旧路径拼接使用的逻辑 |
| `skills/commands.ts` | 两个子命令使用实际安全配置，展示合并目录、来源和诊断 |
| `tools/skill.ts` | 保持只读适配器，调用共同目录访问函数，更新工具说明和来源字段 |
| `agent/channel-runner.ts`、`agent/session/session-host.ts` | 初始加载和资源刷新传入相同的来源及安全上下文；向 SDK 提供最终目录 |

共同加载结果只需包含有效 `Skill[]`、对应来源和诊断。复用 SDK 已有的文件路径和诊断结构，不建立候选生命周期、状态机或独立目录缓存。名称读取查找有效目录中的文件，不能再假定路径一定是 `workspace/skills/<name>/SKILL.md`。

### 4.1 SDK 边界

Pipiclaw 显式加载两个来源，SDK 继续负责技能目录的提示词渲染和 `/skill:名称` 展开。ResourceLoader 禁止默认技能注入，`skillsOverride` 只返回 Pipiclaw 的结果，不再合并 `base.skills` 或其技能诊断。仅设置 `noSkills` 不足以替代最终列表的所有权，因为 SDK 仍可能处理其他显式资源路径。

这项限制只针对技能列表，不通过关闭整个扩展系统实现，也不修改 SDK 私有成员。当前 app 根级 `skills/`、cwd 下的 `.pi/skills/`、项目 `.agents/skills/` 等 SDK 额外发现来源不再进入最终技能列表；这是本次明确来源边界的兼容性变化，需要写入使用文档。

### 4.2 路径规则

两个来源使用实际安全配置和现有路径守卫过滤技能；被拒绝的内容和元数据不进入模型目录或列表。SDK 的发现过程可能已经读取候选文件，本设计承诺的是过滤输出，不将其描述成“被拒绝的文件从未被打开”。

有效技能记录守卫解析后的路径；`skill read` 和 `/skills show` 在读取时再次检查目标，并使用守卫返回的路径打开。引用文件和脚本继续通过普通文件、命令工具的守卫处理，不为共享目录添加默认放行规则。

SDK 的 `/skill:名称` 使用已加载目录和记录的路径；本次不重写其读取机制，也不承诺对并发替换文件提供原子快照。内容扫描控制目录准入，不替代文件权限或命令权限。

## 5. 展示、读取与刷新

- `/skills` 展示按名称合并后的技能，标注“工作区”或“用户共享”；诊断中区分加载失败、可加载的格式 warning 和被覆盖版本。工作区失败而共享生效时必须说明实际使用共享版本。
- `/skills show <name>` 优先展示当前磁盘目录中胜出的有效版本和路径。若没有有效版本但存在可读的失败候选，继续允许用户查看用于排错；有多个失败候选时优先工作区，再按稳定路径顺序选择，并明确标注未加载。被路径守卫拒绝的文件不能通过排错入口读取。
- `skill list` 返回相同解析规则下的目录及诊断，`skill read` 只按有效目录读取。不存在或只有失败候选时返回可恢复错误，指导模型先查看列表诊断。
- 用户报告继续遵守中文文案、单层列表和 `capReply` 预算。创建、修改技能的默认建议仍指向工作区，避免默认修改跨工具共享内容；不新增共享目录的写入权限限制。

启动、新会话和现有资源刷新重新扫描两个来源。`/reload` 更新当前会话的技能快照。扩展现有 `write`/`edit` 成功后的路径匹配，使写入任一技能根目录都能触发当前会话刷新；符号链接目录使用与守卫一致的实际根路径匹配。

实现核对发现旧版本只有资源重载方法与 SDK 命令上下文回调，并未注册 `/reload`。本次在命令目录与 session command extension 中补齐该入口，复用现有资源刷新门，不调用模型，保留会话历史；回合进行中按现有会话命令规则拒绝。

外部工具、shell 命令或其他会话修改技能后，由当前会话执行 `/reload` 生效。不增加监听或跨会话广播。`/skills` 和 `skill list/read` 保留按需读盘的性质，不依赖活动 runner；它们与会话快照共享规则而非共享实时状态，文档说明修改后需要刷新，不增加版本比对提示机制。

## 6. 验证与落地

优先扩展 `test/config-loader.test.ts`、`test/skill.test.ts` 及现有用户文案结构测试，目录规则的输入矩阵只放在技能领域层：

- 两来源并集、工作区覆盖、工作区失败后共享生效、缺失目录和不可读文件诊断。
- 稳定重名选择、多行描述、递归发现及实际文件去重；保留现有内容扫描与符号链接拒绝覆盖。
- 模型工具和用户命令读取胜出文件；实际安全配置的拒绝规则不再只在详情入口生效。

扩展现有系统提示确定性 e2e 链，检查最终 provider 请求包含胜出技能路径、遗漏被覆盖或被拒绝路径，脚本化工具读取正确正文，并在刷新后使用新版本。现有命令 e2e 的 A3 技能调用场景补充 provider 输入检查，证明 `/skill:名称` 也展开同一个胜出文件。还要放置两个正式来源之外的技能，证明 SDK 默认发现不能重新混入结果。模型措辞不作为断言。

所有技能测试显式注入临时共享目录。涉及真实 ResourceLoader 的用例同时禁止 SDK 默认技能注入，确保真实用户目录的技能不会被加载进测试。写入触发刷新在已有资源刷新 e2e 链中补充脚本化写入操作，覆盖共享来源的跨模块接线，不在各适配层重复完整矩阵。

默认不净增 unit/e2e 用例；若现有场景不能覆盖新的跨模块风险，实施记录说明新增原因与用例数变化。新增或扩展的确定性机制断言需做针对性 mutation 检查，至少反转覆盖顺序或恢复 `base` 合并一次，确认对应断言失败并记录。

实施后运行 `npm run typecheck`、`npm run arch`、`npm run test` 和 `npm run test:e2e`。工具说明有模型可见变化，按仓库规则规划受影响的行为探针，有凭据时执行相关 dev cases；记录运行 id、失败归因或无法执行的原因。

使用文档同步说明两个来源、有效技能覆盖、失败回退、来源限制和 `/reload`。更新 `AGENTS.md`、`CLAUDE.md` 中适用的 workspace-only 表述，以及架构说明和技能配置手册；不重写历史 spec，也不增加迁移代码。实现按“共同加载与解析 → SDK 和命令/工具接入 → 刷新、验证及文档”顺序完成，作为一次功能变更交付。

实施结果、验证与运行记录见[验收记录](./acceptance.md)。
