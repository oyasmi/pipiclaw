# 063 — 实施与验证记录

日期：2026-10-27。

## 实现

- `skills/loader.ts` 统一两个来源的 SDK 发现、路径过滤、内容扫描及名称合并。有效工作区版本优先，失败版本不占名；同源重复按路径稳定选择，同一实际文件不产生虚假冲突。
- `skills/catalog.ts` 供命令和模型工具按解析结果读取，不再按名称拼工作区路径；用户可查看可读的失败文件用于排错，模型读取只接受有效目录项。
- 会话通过 `noSkills` 和仅返回 Pipiclaw 结果的 `skillsOverride` 控制最终目录，SDK 负责提示词渲染与显式调用。SDK 额外发现的来源不再混入。
- `/skills`、`skill list/read` 展示实际来源和诊断，命令列表与详情均采用实际安全配置。SDK 格式提醒与真正失败分开处理，多行描述使用 SDK 解析结果。
- 两个技能根目录的成功文件写入触发当前会话刷新，兼顾守卫解析后的路径和关闭符号链接解析时的别名路径。没有新增监听、缓存、用户配置或迁移代码。
- 已同步技能手册、工具和配置手册、部署备份说明、架构文档与项目指令。

实现核对修正了设计对现状的一处误判：旧版只有资源重载方法及 SDK 命令上下文回调，没有注册 `/reload`。本次在既有会话命令层补齐入口，复用资源刷新门，不调用模型、不清空对话；无效参数不会触发刷新。

## 使用边界

共享目录属于运行服务的服务器账号，独立于 app home，缺失时不创建。只支持工作区与用户共享两个正式来源；其他 SDK 隐式来源请移到其中之一。外部编辑、shell 或其他会话的修改需要在当前会话发送 `/reload`；没有跨会话自动广播。技能仍受现有扫描与工具权限约束，不授予额外权限。
