## 开始前

读 [AGENTS.md](../../../AGENTS.md)、[现行评测指南](../../evals.md)及[设计](design.md)。记录起始提交、工作区状态、本机 Node 与评测模型配置。`doctor` 只确认环境，连接状态由首个定向真实样本提供。以分支或隔离 worktree 冻结付费实验输入，保留已有变更和本地原始结果。忽略目录中的历史证据缺失时，用下表中的最小反例重建，不依赖其他机器的绝对路径。

```bash
git rev-parse --short HEAD

npm run eval -- selftest --all
npm run eval -- selftest --case S-net-02
npm run eval -- plan --changed-since 3e3c93d
```

审查起点为 98 项离线评测测试、42 个场景，其中 1 项隔离。以实施时的实际计数为准。每个工作包先扩展已有测试或评分控制，必要的新增机制测试说明旧覆盖缺口、回归风险和净变化。保持阶段可独立验证。涉及生产 runtime、记忆、委派或命令面时，按仓库规则运行确定性 E2E。

## P2 统一计划、准入与计量

1. **冻结选中槽位。** 在 `evals/harness/{selection,cli,cycle,run,schema}.ts` 统一构造和验证计划。显式 case 可重复，`--changed-since` 自动模式限三项，无其他选择条件的 `--profile dev` 保持六项。`plan --output` 保存执行清单，`cycle --plan` 按槽位执行。`cycle` 的便捷调用内部走同一条计划路径。执行前核对 case、fixture、oracle 和执行输入身份，再按 057 完成正式资格检查和有效配置冻结。变更选择报告至少列出命中的路径、代表、未选理由和未映射路径。
2. **集中管理预算。** 在评测调度层用一个已有并发池或同域调度器核算准入。保留 `--max-cost-usd` 与 `--max-wall-minutes` 的计划包络语义，另提供 `--max-tokens` 与 `--max-elapsed-minutes` 作运行级停止调度阈值。先确定未知累计量策略并写入计划，默认在显式 token 阈值下，遇到影响后续准入且无法估计的模型用量即停止投放。账本偶发延迟允许等该槽位收束后再判断。当前 `T-run-01` 的本地无模型生产者可单列，外部费用继续报告未知。可保守选择在槽位结束时更新 token，通过观测确认没有双计。时间阈值使用单调时钟并在准入处重查。
3. **保留未运行的槽位。** 按计划标识显示 `not-started` 及批量预算原因。将已结算量、在途归并和剩余预算写入运行证据。`resume` 只可使用现有兼容性与归档完整性约束，并延续原累计量与预算，防止重复消耗或重复记账。计划包络拒绝为零模型调用。批量预算截断时以不可判定结束，发现明确硬违规时沿用更高优先级。
4. **让报告支持付费决策。** 在 `resources`、`report-render` 和 `diff` 扩展已知与未知用量、token/成功、费用/成功、运行/队列/评分耗时。按 case 和试验种子展示配对分歧。保留有明确验收事件的场景的首个有效交付耗时，其余显示缺样本。`candidate` 默认每边每题 3 次。扩展试验使用不同且预先声明的槽位号，保证同一对复用 seed，下一批使用新 seed。先用现有 CLI 和少量记录完成配对工作流，配对调度平台无需成为交付依赖。

验收应在本地 mock 中覆盖下列行为。每个进程入口断言实际请求数或启动槽位数，避免只测报告字符串。

| 机制 | 验收 |
| --- | --- |
| 计划一致性 | 以历史的 36→6 覆盖同类问题。生成后执行一次正例，ID、顺序、次数、seed、预算一致。改变一个身份条件另跑反例，provider 请求保持 0。空 diff、纯文档、混合已知和未知路径、显式过滤交集都有可复核选择理由。 |
| 并发停止调度 | 借助 mock provider 的 `hold` / `release` 造出两个在途槽位。阈值满足后释放，在途结果结算，第三个及以后不启动。使用测试注入的时钟拉过时间阈值，覆盖资源不可用、迟到和超额。检查未启动的槽位、硬违规优先级，以及续跑不会从零重新计量。 |
| 费用与 token | 观察层与 ledger 同一笔只算一次。覆盖账本分项推导合计、外部未知、零成功、真实开销和预算触发。分别核对每个分母，以及花在失败试验上的用量仍进入成本。 |
| 配对可比性 | 有效同条件组能输出逐槽位与方向计数。更换 seed、条件、grader、角色执行器或预算后，给出不可比原因。缺失槽位应出现在覆盖报告中。 |

按照 [现有评测指南](../../evals.md) 的入口风格更新帮助。回避把 `evals/harness/run.ts` 继续做大，按职责提取计划或准入逻辑到该目录。**P2 的真实模型预算为 0。**

## P3 提升核心用例的信息量

1. 在用例目录与 gates 中记录保留项、候选替换项以及保留原核心的回退条件。先把 `C-existing-01` 和 `I-inbound-context-01` 当作晋升候选，保持 12 项正式核心不变。新项两个都取得计划的 3/3、完整证据和可重放性时，再一次完成等量替换，旧用例转入扩展。保留现有 `C-test-proof` 和 `D-merge` 的定向执行能力。
2. 落实 `M-abstain-01` 替换长离题问答，收紧 `M-extract-01` 的事实判定，加入 `T-ask-01` 与委派核验的自然变体。每次替换写明模拟的使用场景、隐藏状态、允许路径、全部验收项和最重要反例。优先使用合成或脱敏实案。有证据与缺证据共享接近的提问和不同环境输入，防止任何一律作答策略通过。对旧 ID 保留历史记录的查看能力，旧档若无当前评分器则明确标注。
3. 测量 `M-overflow-01` 的上下文、反思占比和慢路径。在同一索引预算下减少夹具冗余，仍保持干扰密度。离线证明目标在实际 bootstrap 索引中缺失、可通过恢复路径找到、降到边界以内时资格条件会失效。记忆反思如果属于真实产品使用的附随开销则保留并单列。如果隔离关闭维护以测单一召回路径，显式冻结该评测条件，并保留一条生产默认路径测反思相关风险。
4. 为自然变体记录选择及识别规则。用已有编号、家族和隔离机制组织备用变体，用选择日志证明默认付费计划的总规模没有扩大。隔离用例仅显式付费执行。付费 worker 使用独立的试验目录和现有守卫，合成夹具使用本地替身。

本阶段结束先执行全部离线 controls。对新场景，逐项说明一份能过的结果、至少一份任务失败或越界的结果、一个等价完成，并确保其结论不靠指定工具名或固定句式维持。`C-existing-01` 原始 diff 和钉钉旁支任务的未推进分别作为保护证据。

## P4 本机实测、参照与交接

预算按 [设计 §5](design.md#5-d4-token时间和配对实验) 执行。以下命令采用本规格的目标 CLI，P2 完成后用 `eval help` 验证参数。

```bash
npm run eval -- plan --case M-overflow-01 --case U-desk-cwd-01 --case C-fix-01 --concurrency 2 --max-tokens 200000 --max-elapsed-minutes 3 --output evals/results/spec071-dev-plan.json
npm run eval -- cycle --plan evals/results/spec071-dev-plan.json
npm run eval -- plan --profile core --concurrency 2 --max-tokens 2400000 --max-elapsed-minutes 15 --output evals/results/spec071-core-plan.json
npm run eval -- cycle --plan evals/results/spec071-core-plan.json
```

1. **定向冒烟。** 先跑示例中的三个样本，验证模型连通、证据重放和资源计量。需要完整六项的实际墙钟时，从一开始就用完整 `dev` 计划代替该三项计划。通过后运行新的 `M-abstain-01` 一次，并为任务侧自然变体安排一个真实样本。
2. **验证候选与冻结核心。** 在隔离 worktree 配好拟晋升的 catalog 和 gate，再对 `C-existing-01`、`I-inbound-context-01` 各运行 3 次，关闭 judge，要求证据全部重放。当前 `caseHash` 包含目录元数据，此顺序能保证候选采样使用晋升后的 case/oracle/fixture 身份。满足 P3 条件后用该组成执行一次完整 `core`。候选未达到要求时，在原核心组成上执行周期，并记录未晋升原因。若核心周期失败，保留首次失败和预算，后续重跑须有针对已定位问题的修复或已冻结的扩样规则。
3. **控制总投入。** 常规真实验收包括最多 6 个 `dev` 槽位、2 个新增自然场景定向槽位、6 个核心候选槽位及 36 个核心槽位，共 **最多 50 次试验**，每批以实际冻结清单为准。少量定向和候选批次单独预设预算，核心沿用设计目标。可复用已有同身份样本。配对工作流先用 mock 验收，有真实的模型或 runtime 选型才另开付费 A/B。
4. **归因和退出。** 模型配置缺失、提供商不可用、达到资源上限、未获样本时，均记录实情及受影响场景。报告离线实现、真实质量验证、新参照三个状态。只有完整 required 集合、冻结 gate 通过、无硬违规、样本完整和证据全部重放时生成自动参照。`PASS WITH FINDINGS` 的首次失败及影响保留在记录中。
5. **收尾。** 更新 [评测指南](../../evals.md) 和 [spec 索引](../README.md)，在本目录新增 `acceptance.md`。记录提交、测试与用例净变化、负向验证、每批 run ID、可比性、现场/重放计数、失败归因、阶段 token、已知费用、未知用量、实际时长和预算命中。大型本地产物继续留在忽略目录。
