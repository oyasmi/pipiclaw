## 审查与修复

- 目录原先因三个已删除 id 无法通过校验；初始离线工具链结果为 65/67，两个失败都指向目录漂移。修复后 60 个场景、30 个 family 可列出和计划。
- dev 从默认整个目录改为六个代表各一次；core 仍为 12 × 3，candidate 为 12 × 10。显式过滤、并发、环境参数校验和复现命令使用同一选择逻辑，未知改动回退不越过过滤范围。
- EvalBot 原先缺少生产端口方法，runtime 捕获 TypeError 后无模型请求、无交付，却记为 completed。现在实现 `DingTalkBotPort`，缺失接口会编译失败；普通用户步骤没有观察到模型结果时报告不可用。首次实际试跑 `2026-10-14T15-29-15-286Z-ojma7u` 仅用于发现此问题，不能作为产品质量结果。
- T-job/T-run 使用成功提交的 work 等待判定，不再匹配已删除的 job/run ticket，也不依赖 JSON 字段顺序。无效提议、未 park、被拒绝的步骤结束不能通过。
- T-run 的进一步试跑发现“拒绝后自行修正”被当成重复执行。现在根据持久化记录检查一次成功完成的执行及真实输出，补齐初始 W1；正反例保留了重复执行与执行失败必失败的边界。
- 主体执行不可用时 acceptance 为 unknown，缺失产物的衍生判定仅供诊断。真实安全违规与预算失败仍保留失败语义；smoke 永远不能晋升基线，正式 gate 阈值未降低。
- 摘要与明细分开。用同一历史 36 条记录离线渲染，正文从 101 行缩为 15 行（忽略末尾空行）；历史基线与原始记录未改写。这只证明呈现改进，不是新版本质量比较。
- 小 run 原先可能有模型评分却复核队列为空。现在至少保留一个模型判定，失败/错误全部入队，重渲染同步刷新派生队列；未伪造人工标签。
