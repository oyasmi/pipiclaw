# 一次性迁移说明：由 AI agent 将现有数据整理到 desk 布局

本文用于一次具体部署的离线迁移，不是产品运行协议，也不是可直接照抄执行的通用脚本。

**目标是 spec 060 的 desk 版本。先确认实际安装的代码已实现 `desk.json`、`desk-bindings.json` 和 `/desk`，再转换数据。不要把转换后的 home 交给仍只认识 dot 的版本启动。** 对旧 dot 版本的必要运维同样先核对实际读写格式，不机械套用目标布局。

可以直接让有服务器文件访问能力的 AI agent 阅读本文、目标版本源码与现有 home，完成迁移。默认目标是把日常工作放在 `default`；已有明确的工位划分和绑定应保留。工位合并是数据整理决策，不能由一个目录名相似就推导出来。

## 1. 给执行 agent 的任务约定

先确认实际 app home、源版本、目标版本、当前进程、数据规模和可用备份。读取目标版本的路径函数、记录类型、任务/事件格式和后台持久化实现，以它们为准。列出本次实际需要处理的数据和去向后再动手；遇到无法恢复频道地址、互相矛盾的归属或会覆盖的内容，保留原件，说明具体选择及影响，需要用户决定时只问该项。

允许为本次明确的数据写临时命令、查询或小工具，但不要将它们加入产品源码、打包文件或长期测试，不重新建设一个通用迁移器。不修改用户的技能、人格或工作内容来迎合文件格式，不升级本次无关的依赖和业务 schema。未经授权不启动正式 daemon 或向钉钉发送测试消息。

## 2. 停机与备份

- 先停止新的任务与事件派发；在旧宿主仍能管理时确认后台 job 和外部委派的情况，等待需要保留的工作结束，或按授权取消。daemon 停止后 detached 进程仍可能继续写旧路径，不能只凭 daemon 已退出就开始搬目录。
- 停止 daemon、TUI 和服务管理器的自动重启，确认所有可能写入本次 home 的进程都已退出。跨主机搬迁必须先结束在途外部进程，持久化 pid 不能在另一台机器上恢复。
- 对整个 app home 做可恢复的完整备份，保留权限、时间与必要的链接属性，并记录源程序版本。workspace、state、配置和凭据必须对应同一个停机快照。备份放在工作区外，不在聊天或报告里输出密钥。
- 优先在备份的独立副本上整理。副本不得连接钉钉、运行定时工作或产生真实外部委派；保留原 home 路径用于判断绝对引用，不把“副本路径”误写成最终生产路径。

## 3. 按实际源格式选择转换范围

### 已有 dot 布局

通常是一对一移动，保留逻辑名、频道地址、会话区名和业务 id：

| 原位置或字段 | desk 目标 |
|---|---|
| `workspace/dots/<name>/` | `workspace/desk-<name>/` |
| 工位目录内 `dot.json` | `desk.json`，`name` 仍为 `<name>` |
| `workspace/dots/bindings.json` | `workspace/desk-bindings.json`；绑定值的 `dot` 改成 `desk` |
| 当前机器记录中的所有权字段 `dot` | 按目标 schema 改为 `desk`；值保持逻辑名 |
| 仍有效的旧工位绝对路径引用 | 指向搬移后的实际目标；保留自定义 cwd 的真实语义 |

`state/jobs/<name>/`、`state/subagent-runs/<name>/` 等若已按逻辑名组织且名称不变，就不需要为了术语改名而再搬一次。检查文件内部字段和路径即可。没有 `default` 时准备空的默认工位；不要把已有 `main` 自动更名、合并或改绑为 `default`。

### 更早的按频道目录布局

先从元数据、频道索引及记录里恢复真实频道 id。群地址可能含 `/`、`+`、`=`，旧目录可能做过转义；不能把转义后的目录名直接当作地址。多个来源冲突时先查明。

默认把日常频道的工作归入 `default`，但先检查文件、记忆、任务与后台记录是否能无损共存。每个频道在目标工位保留独立会话区，按目标规则分配 `dm-N`、`group-N`、`tui-N`，保留 session 文件与活动指针的对应关系。终端使用频道 id `tui`，不伪造钉钉绑定。

如果任务或记忆还是比目标更老的格式，按这批实际文件和目标 reader 整理，不要求运行某个旧迁移脚本或提供某个 `.done` 文件作为资格证明。数据本身和可核验结果才是依据。

### 混合布局或已做过部分搬移

先比较内容、归属与已有记录，确认上次操作完成到哪一步。不要重复运行整批覆盖操作，不以文件较新就判定正确。不确定时从一致备份重新整理；保留能够解释中断位置的操作记录。

## 4. 只处理实际存在的关联

下表是盘点提醒，不要求每次执行全部步骤或建立通用转换框架。

| 数据 | 必须保持的关系 |
|---|---|
| 共享配置与能力 | workspace 根 SOUL、AGENTS、共同 MEMORY、ENVIRONMENT、skills、角色目录继续共用；不复制成每个工位的人格 |
| 局部 SOUL/AGENTS | 核对旧覆盖内容。共同规则可整理回根文件，项目工作说明另存为合适的工作资料；有意图差异时报告，不拼出互相矛盾的人格 |
| 记忆与日记 | `memory/` 是事实源，生成的 MEMORY 索引可重建；保留来源、遗忘记录与用户显式事实。共同背景不被工位索引覆盖 |
| 会话与反思 | session、active-session 指针、context/log、会话目录登记相互匹配；保留待处理反思、完成回执、游标与已处理边界，避免重复学习 |
| 任务与事件 | 保留 task/event id、任务会话、循环日志、工作项及实际投递 channel；旧任务缺失 channel 时从真实归属补齐；事件模板与任务引用仍能解析。仍需查询的事件历史也整理为明确的 desk 归属，目标 reader 不再按频道集合猜旧记录属于哪个工位 |
| job 与 delegation | 保留业务 id、状态、产物引用、usage/settlement/lease/wake 幂等凭据；不能为躲避冲突随意改 id 或清空完成标记 |
| durable dispatch | 当前记录的所有权字段、派发 id、嵌套 wake id 及生产者记录中的消费凭据必须一致；逻辑名不变时不要无故重生成 id |
| 用量 | 保留历史金额、token 与频道归属；目标 reader 若按 desk 汇总，需要转换相关结构字段，不能让旧字段被默默漏计 |
| 绝对路径与 cwd | 包括 session header、产物、任务资料及脚本配置。只改确实指向已搬数据的引用；自定义 cwd 指向外部项目时通常保留。不要用一个全局字符串替换处理二进制、路径前缀碰撞或普通叙述 |
| 频道索引与路由 | CHANNELS 可从真实地址和新绑定再生成；保留钉钉路由元数据以支持原频道主动推送 |

历史聊天里的普通“dot”字样、日志描述、评测封存证据不需要为了术语整洁全部改写。历史评测需要重放时转换独立副本，保留原件与来源。对当前程序仍会读取的机器字段、指针和引用，必须按目标 reader 逐项处理，不能以“历史数据”跳过。

## 5. 冲突与合并

不覆盖重名文件，不按时间或频道类型自动决定哪个版本是真相。一个工位内重名的 task/run/job id 可能牵连等待条件、任务会话与完成消费凭据；重名记忆也可能分别属于不同的人。先比较实际内容和引用，再决定合并、保留为不同名称、归档或分到不同工位。

尽可能采用一对一搬移保全状态。为合并改 id 时必须同步所有关联并留下映射；若无法证明完整性，保留为独立工位比丢弃另一份工作更合理。日记和审计的整理需保留来源与顺序，不能静默拼接冲突记录。默认工位是新频道的默认选择，不要求迁移时强行合并所有既有工作。

确实不再有用的历史中间文件、旧迁移标记和旧容器目录，在备份和核验完成后移出活动 home；当前程序不依赖它们。不要以软链接、旧字段副本或保留旧 reader 来掩盖未完成的转换。

## 6. 核验后再切换

- 对照迁移前盘点，逐项核对工位、绑定、会话、事实、任务、事件、后台工作与用量。每个缺项或归档项都能说明去向；多个来源不得覆盖到同一个目标。
- 用目标版本的 reader 在离线副本上验证记录。可复用现有函数或写本次临时检查，不在源码增加迁移模式。验证记录逻辑名、绑定目标、会话目录唯一性、任务投递频道、派发凭据与有效路径。
- 确认根共享文件未被索引覆盖，当前格式无需旧字段/旧目录即可读取；缺失或损坏的原工位没有被伪造为空工位。没有事实变化时不触发模型反思来“修复”迁移。
- 保持自动服务关闭，先做本地只读检查。获准启动正式实例后，检查 status、工位列表、任务诊断、事件与委派状态；真实频道消息及会产生模型费用或通知的验证按本次授权执行。
- 观察旧工作是否只恢复一次、通知是否回到原频道。若有仍在等待的工作，验证其等待凭据，不能只看程序启动成功或普通聊天成功。

失败时先停下所有新写入者，将程序版本和完整 app home 恢复到同一个备份快照，避免新程序配旧数据或新旧 state 混搭。切换后如已产生新工作，先保全这些增量，再决定回退，不能直接覆盖掉。

## 7. 本次操作留下什么

给出一份简短记录：源/目标版本、实际 home、备份位置、源到目标映射、冲突处理、未搬数据、验证结果、仍未验证的后台工作及回退位置。不要输出凭据。

记录和备份留在部署者选择的位置，产品运行时不读取，不要求固定名字，也不创建迁移完成/中断协议。操作结束后删除临时工具；这份说明在相关旧部署全部处理完后也可以删除，正常产品启动、测试和工具调用不应依赖它。
