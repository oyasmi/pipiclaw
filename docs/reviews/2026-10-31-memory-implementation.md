实施日期：2026-10-31。对应[分诊方案](2026-10-30-memory-triage-and-plan.md)和[原始审查](2026-10-30-memory-management-review.md)。没有引入新的依赖、配置开关、后台服务、目录种类或持久化字段。

## 实施结果

| 范围 | 结果 |
| --- | --- |
| R1 | 共同路径入口校验合法名称；命令和工具提供各自受众的纠正指引；列举和单条读取不跟随条目符号链接 |
| R2 | 为完整后缀预留名称长度，最大长度冲突和后缀位数增长均能终止 |
| R5、R6 | 用户显式替换设置现有 `source: user`；自动 add/update 都检查精确遗忘；只有显式用户写入成功后撤销对应阻挡 |
| R9、R7 局部 | 共享背景的前言、普通正文、H2 标题（包括空正文）可搜索；workspace 前言和省略提示计入 units/chars 预算 |
| R4 | 后台 add 对归一化 description、type、完整正文做精确去重，不把重放当 touch；审计错误独立告警，不重跑已提交业务 |
| R8 | 先执行非删除操作，策略或 store 拒绝内容写入、发生 I/O 错误或更新/删除目标冲突时，不执行本批自动删除；独立的合法清理仍正常工作 |
| R3 正常多轮路径 | 根据清洗后序列化大小选择连续完整交流，逐批推进现有 entry 游标；未完成增量不刷新完成时间，孤立用户问题等待回答 |
| R11 | 真正的 runtime `/new` 以及 SDK 会话切换都在切换前保存旧素材；冷热路径复用 `.memory-work`，不等待模型、记忆锁或会话初始化 |
| 诊断与清洗 | 审查日志保留删除原因、拒绝和采样范围，不复制整段对话；journal 的模型输出复用密钥清洗 |

## 恢复实现的两个细节

同一 conversation 的全局游标可能已属于新会话，不能拿它覆盖旧快照的局部进度。工作文件保留原始稳定 id，批次完成后用同样的 `entryIds/messages` 字段原子保存剩余素材；不增加子消息游标或另一份状态记录。全局游标属于其他范围时保留它，旧工作靠剩余素材继续，完成后照旧写 `.done` 再移除素材。

初次发布使用已经写好并同步的临时文件加独占链接，随后移除临时文件。重复 enqueue 不能覆盖部分消费后的快照。旧工作存在时，idle 和 shutdown 不先提交新会话的直接反思；聊天仍可继续。这是现有边界工作生命周期的调整，不是模型操作事务或持久化协议版本升级。

已经关闭的快照中若只有用户事实，允许反思该用户输入，避免永远等待一个不会再出现的回复。活跃会话的孤立用户输入仍保持待处理。

## 明确保留的边界

- R4 是有限缓解：多个文件仍可能部分成功，模型换一种措辞时仍可能形成重复，没有跨文件原子性或 exactly-once 保证。
- R3 单个超大交流仍按原限制采样，日志明确记录大小及范围；未实现持久化子消息分片。
- R7 保留 user/feedback 全给策略及完整反思索引，没有引入动态模型预算。
- R10 保留下一次反思前清理的语义；到期不是读取 TTL，文档已说明。
- 遗忘仍是精确归一化哈希阻挡，不抹除原始历史或当前模型上下文，不声称识别同义改写。

## 测试准入与数量变化

unit 净增 **5** 例，其他现有场景直接扩展；deterministic e2e 净增 **0** 例。

| 新增 unit 场景 | 既有覆盖不足与项目风险 |
| --- | --- |
| 隔离进程验证最大名称冲突 | 旧测试只检查名称形状和短后缀；同步死循环会冻住整个测试/daemon，必须能从外部终止 |
| 专用记忆读取范围 | mtime 和普通读取测试不能发现合法别名跟随符号链接或非法名称越界；可能泄露其他工位内容 |
| journal 故障后的精确重放 | 单次成功写入无法覆盖部分副作用；故障重跑会增殖重复记录，同时需证明不同正文和用户元数据不会被去重误伤 |
| 替代写入被拒/失败时保留原项 | 原有置信度、上限、密钥与删除各自测试没有覆盖它们的组合；可能删除唯一事实。矩阵留在反思域，不重复到 e2e |
| 完整交流分批与未回答尾部 | 原有一个短窗口的游标测试无法检出跨预算跳过或孤立用户事实被确认；会造成自动记忆静默漏处理 |

现有 e2e M3 扩展为真实多批 source → provider → 文件/游标链，验证每个中段标记进入且只进入一次对应反思，以及重复后台 add 不增殖文件。现有 compaction SIGKILL 链继续覆盖原压缩 producer，并增加真正从 transport/runtime 入口发送的冷 `/new`、再次 SIGKILL 和关闭空闲维护后的恢复。

## 破坏验证

以下修改均已确认编译可执行并因目标断言失败，之后恢复原代码。临时编译错误不计为检出回归。

| 故意破坏 | 观测 |
| --- | --- |
| 恢复拼后缀后截断 | 隔离子进程超时，名称用例失败 |
| 移除后台精确去重 | journal 故障重试后出现两条事实，重放用例失败 |
| 绕过替代失败保护 | secret 替代未写入，原事实却被删除，安全删除用例失败 |
| 取消按预算选批 | e2e M3 只发生一次裁剪反思，分批/全素材覆盖断言失败 |
| 移除 runtime `/new` 的快照保存 | 冷 `/new` 没有产生待整理工作，进程恢复链失败 |

验证过程中纠正了一个测试入口错误：最初的冷 `/new` 用了 worker 的 SDK 直调入口，移除 runtime 保存后测试仍绿；改用 worker 的 `send`，经过真实 runtime 路由后，破坏验证变红。另一次新增断言因旧素材已经全部整理而没有新模型请求，补入未整理的 fixture 事实后再验证。这两项属于测试设计修正，不记为产品故障或质量通过。
