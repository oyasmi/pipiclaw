# 单测价值审计与数量控制

日期：2026-10-13。范围：`npm run test` 收集的 137 个单元/集成测试文件；结合已实施的 spec 054 分层和 spec 048 测试分层审计。spec 054 的历史实施记录保持原样，本次按用户要求单独删减测试。

## 结果

| 指标 | 清理前 | 清理后 |
| --- | ---: | ---: |
| Vitest 实际执行的单元/集成用例 | 984 | 952 |
| 单元/集成测试文件 | 137 | 134 |
| 单元/集成测试代码行数 | 26,462 | 25,718 |

删除 31 个低价值用例；工具名验证的正反边界合为同一个用例，减少 1 个。技能解析诊断、提示词指纹变化两项有效检查迁入已有领域测试，移除其重复 SDK loader 脚手架。单测代码净减少 744 行。未增加单测用例，没有修改测试发现范围、跳过用例、放宽超时或降低校验门槛。

主要收益是减少重构时需要同步修改的测试、无关断言和 fixtures。清理前单测一次运行约 56 秒；这是单次观察值。用例减少比例约 3.3%，不能据此声称运行时间同比下降。慢用例主要守住进程恢复、委派生命周期、记忆反思与真实 I/O，按故障价值保留。

## 后续准入规则

规则已写入根目录 AGENTS.md 和 CLAUDE.md，供后续 AI 实施者直接遵守。

- 现有功能默认不净增单测用例。先扩展最接近的有效场景或替换弱用例；新增必须写明故障、影响、现有覆盖不足和数量增量。
- 纯搬迁、拆分、重命名、依赖注入只调整已有测试和 fixtures，运行 architecture/e2e 门槛，不为每个拆出的 helper 新建测试。
- 一个边界矩阵放在拥有该决策的领域；adapter 只验证不同的参数转换/守卫，runtime 用确定性 e2e 验证真实链路。
- 普通文案、模板参数、展示顺序、私有字段名不做精确断言。机器协议、持久化格式、escaping、实际操作 id/path 可以精确断言。
- 能说明一个合理错误实现及其项目影响，才值得添加。禁止以覆盖率、测试数量、每函数一测为理由新增；也禁止把无关失败模式挤成一个用例制造数量下降。

## 验证

最终验证全部通过：`npm run check`（lint、typecheck、arch、deadcode、134 个文件 / 952 个单元与集成用例）；`npm run test:e2e`（24 个文件 / 55 个确定性用例）。生产 TypeScript 去除注释后与清理前一致。

对移入现有 commands e2e 的事件删除检查做 mutation check：暂时让 router 的 events 分支返回空回复、不执行处理器，确认 A2 因事件文件仍存在而失败，然后恢复实现。该检查只增加已有用例的可观察副作用断言，不增加 e2e 用例。

最终两组全量验证并行运行，单测约 117 秒、e2e 约 201 秒；它们与清理前单独运行单测的 56 秒不具备直接比较条件。本次未声称验证运行时间已显著下降，后续评估速度应保持相同机器、并发与缓存条件。这里的确定收益是减少无效用例、冗余脚手架和重构时的同步维护量。
