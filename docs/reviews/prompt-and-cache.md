# 提示词、手册与请求缓存复盘

11 月的几轮审查先缩工具描述和常用手册，再接入会话身份并减薄回合上下文，最后完成手册短路径及内部委派缓存。当前设计、最终用量和运行记录见 [Spec 069](../specs/069-prompt-cache-and-playbooks/design.md)及[验收](../specs/069-prompt-cache-and-playbooks/acceptance.md)。

## 保留的设计原则

- **使用真实会话身份。** 主会话和任务使用 SDK 会话 ID，内部 worker 使用 run ID，一次性 Web API 请求使用独立身份。缓存资源随会话生命周期释放。Codex 路由指纹包含模型、实际端点和解析后的鉴权头，且按会话保存。父子请求交错时，单槽指纹会漏掉父会话路由变化。
- **保留可复用前缀和当前事实。** 稳定的规则、工具声明和手册目录留在前缀；cwd、频道、待答任务等回合事实只带当前判断所需内容。采用压缩后的新投影要重判记忆与任务契约是否仍在，按需补回后重新估算预算。
- **常见操作短路径，复杂操作按触发点读手册。** 有明确时间的单次文本提醒可直接调用。低频的任务恢复、独立核验、事件传感器、临时内置委派各自有可发现的手册。角色目录帮助选择合适的执行者，完整交接和失败处理仍有入口。工具描述缩短时应保留默认值、单位、权限和排他字段。
- **按请求形态管理缓存。** 连续工具循环可以复用前缀，严格单轮的记忆反思和冷检索摘要显式禁用缓存。对长期空闲后的续聊，需要单独测量保留期开销及收益。外部 CLI 续接传本轮指令，并尊重 CLI 自己的系统提示入口。

## 怎样验证变化

1. **检查真实请求。** 本地 Codex WebSocket 对照用相同提示和两轮对话。无会话 ID 时用了两条连接，第二轮发送 3 项输入。有稳定 ID 时复用一条连接，第二轮带 `previous_response_id`、发送 1 项输入。更换 ID 后连接隔离。这个探针只证明传输机制。
2. **分开记录长度、计量、费用和耗时。** `playbooks:measure` 的单位用于离线长度对比。缓存读比例应按普通输入、缓存读和缓存写的总和计算，另外记录读写费用、模型请求数、首输出和最终交付耗时。比较冷启动、连续轮次、空闲续聊时，同时记录实际发送内容及是否发生续接。
3. **确认有效操作与最终产物。** 11 月 17 日离线基线的聊天工具定义从 3,342 降到 2,750 单位；11 月 18 日最终版本按相同试验口径将常用任务首步必读正文从 1,322 降到 772 单位。验收抽样中，最终的指定时间提醒由首先读指南变为首次调用即创建，两个变体各用 2 次响应。复杂任务依旧核对真实任务状态、投递及产物。具体数据见 [Spec 069 验收](../specs/069-prompt-cache-and-playbooks/acceptance.md)。

11 月 18 日一次早期定向试验中，`T-ask-01` 与 11 月 17 日样本均为 11 次主体请求，缓存读取从 13,696 / 79,604 到 54,912 / 78,798 输入 token。这是两次独立运行。同期 `U-desk-cwd-01` 和 `M-compaction-01` 均触及回合预算且回放结论不一致。最终验收仍有两处回放差异，分别涉及 cwd 绝对路径和封存策略排除的文件，根因、run ID 与阶段以各自的原始记录为准。

## 仍待验证的工具发现

工具精简和手册短路径完成后，按需声明要用新的直接调用基线测量。先确认候选实际低频、发现结果可追加到暖前缀，并检查 `/reload`、压缩、恢复、备用模型和各 profile 的权限。常用提醒与事件工具在同一入口，延迟它可能增加常用路径的模型往返，试点可以只用 `subagent_inline` 并与既有开关对比。按需声明与程序化查询建议独立试验，详见[工具编排草稿](./2026-11-17-tool-orchestration-proposal.md)。
