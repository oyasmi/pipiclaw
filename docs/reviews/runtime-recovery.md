# 运行时恢复与投递复盘

输入进入会话、日志写入成功、渠道接受消息、进程真正退出、Git 确认可删，都是恢复时需要分别核实的事实。

## 任务车道与关闭

| 原先的失效窗口 | 保留的设计与验证要点 |
| --- | --- |
| 认领步骤后崩溃，输入尚未进入会话却被视为已消费 | 输入先落任务日志，稳定 ID 随正文进入会话。发现实际会话 JSONL 有该条用户输入才写 `input_ack`。在认领后、会话落盘前杀死进程，新 daemon 应将未消费输入送到供应商。 |
| 提问未到达渠道，任务却一直等回答 | 提问的等待状态与送达确认分别记录。缺确认时补发并退避，重启继续。步骤入口统一重验开关、退避和执行资格，首次扫描、连续推进和后台唤醒都受约束。 |
| 日志已写而说明未更新，重启丢失状态或重复记账 | 日志带状态检查点，读取和对账重放未应用的检查点，结算按引用去重。轮转优先保留未消费输入和必要恢复依据，活动日志可以暂时超出大小目标。任务正文读改写也要参加同一锁协议。 |
| 暂停或取消后，旧步骤还在写 | 先关闭新步骤的准入，给旧步骤退出时间。超出宽限时退休 runner 并保留它的占用和跟踪，等实际退出后再恢复该任务。关闭前在锁内复核说明、状态、工作项和执行生命周期，外部管理器查询留在锁外。 |
| 归档发布了一半，恢复误判为新旧冲突或发出成功回执 | `.closing` 记录关闭快照和日志分片指纹。完整归档发布前保留活动数据，识别同次提交已发布的部分后续做，遇到不同内容保留现场。档案完整发布后才发送已预备的完成回执；JSONL 无换行残片单独隔开，防止吞掉下一条完整记录。 |
| 投递失败、确认缺口或损坏记录阻塞队列 | 先落盘后发送，最终报告确认后再归档。渠道已接受、本地未确认时可能重发，同任务顺序保持。已知归属的损坏记录留在原处并隔离到任务，归属未知时暂停投递并保留入队。远端接收表示渠道接受，用户阅读是另一个事实。 |

当前换绑行为见[任务指南](../events-and-tasks.md)和[工位设计取舍](./personal-workflow.md)。旧报告中“换绑会冻结任务”的结论来自早期实现。应用发出取消信号后，已经开始的任意命令或外部副作用仍可能继续。报告中的未知费用保留为未知，已知费用小计和步骤限制仍然有效。

## 后台完成与输出

- **调度延迟按阶段定位。** 区分工作实际结束、运行时观察、结算持久化、投递入队和模型消费。外部 run 在当前进程优先用进程 close，重启接管补观察；后台作业 watch 只提示重新核实，持久记录与探测才确定终态；频道容量释放通知可以加快重试，仍由现有 lease 和退避控制。原排查见 `f171b18:docs/reviews/2026-11-04-tool-and-delegation-latency.md`，实施及配对证据见 [Spec 067 验收](../specs/067-execution-latency/acceptance.md)。
- **Git 状态未知时保留。** Git 检查失败、工作树仍在使用或 Git 拒绝普通删除时，保全工作树、分支和恢复元数据。清理需从检查前到删除完成持独占保护，派发和续接使用同一路径冲突规则。普通只读 run 的使用登记也会阻止清理。真实 e2e 用受控外部 CLI 续接，跨过 GC 到期后再结束，分别去掉续接登记和清理冲突检查都会丢文件。原记录见 `161f31b:docs/reviews/2026-11-17-worktree-cleanup-hardening.md`。
- **旧回合只能清自己的登记。** 停止、队列容量通知和退休用 runner 与 generation 校验归属。关闭时追踪已开始的清理和持久写入，无法确认写入停止时保留 daemon 锁直至进程退出。仅 `ENOENT` 代表持久记录不存在，损坏和 I/O 故障应保留证据，并尽可能让健康记录继续。原记录见 `0a07198:docs/reviews/2026-11-08-runtime-integrity-repair.md`。
- **运行环境变更要验证所有执行入口。** 工位 cwd 变更曾只在部分入口生效。验证应跨过工位切换，同时检查内置文件工具、shell、后台作业和事件前置脚本的实际目录，以及缓存的 runner 是否更新。事件定义热更新应验证旧计时器已停且参数可往返。原记录见 `7eb473b:docs/reviews/2026-11-15-deep-review-and-roadmap.md`。
- **钉钉卡片按已确认的展示快照续写。** 每次窗口收缩有新周期，迟到响应只能确认旧周期。增量发送结果不明时先发新周期的完整快照，再继续追加。测试覆盖连续收缩、迟到确认和增量已生效但响应丢失。真机动画与远端缓存的影响当时未定位。原记录见 `71849b6:docs/reviews/2026-11-05-dingtalk-progress.md`。

## 后台压缩

候选摘要只在内存中准备，绑定会话、模型和原始前缀。采用前重验身份及前缀，在安全请求边界提交，保留生成期间追加的尾部。压缩无法提交时隔离可能不一致的会话投影，原始 JSONL 仍可恢复。摘要的期限、鉴权及重试共用预算，长输入按连续片段递进摘要，工具内容限幅时留原始条目定位。发送前采用压缩后，应在新投影上重判是否需要补回记忆或任务契约。参见[运行机制](../runtime-mechanisms.md)和[缓存与上下文复盘](./prompt-and-cache.md)。

原始两批记录见 `e265956:docs/reviews/2026-10-22-compaction-implementation.md` 和 `e265956:docs/reviews/2026-10-22-compaction-background.md`。后台探针首轮出现字段改名且超调用预算，不能从当时产物判定失真发生在哪一段。后续独立试验增加检查点证据、明确续接验证路径，最终两项定向探针 2/2、六项日常探针 6/6。最终 run 分别为 `2026-10-22T16-30-13-904Z-i4neu0` 和 `2026-10-22T16-30-13-952Z-9t2daw`，首轮失败为 `2026-10-22T16-10-57-768Z-x82fmx`。
