# 记忆一致性与恢复复盘

2026 年 10 月 30–31 日的审查、分诊和交付聚焦反思实际读到的素材、部分写入的重试，以及用户指示在不同入口的一致性。面向用户的文件组织、搜索和观察期语义见[记忆指南](../memory.md)。

## 修复与保留边界

| 决策 | 实施与边界 |
| --- | --- |
| 名称和路径属于存储层 | 由共同入口校验名称，读取和列举避开符号链接。重名后缀先算长度再预留空间，避免最大长度发生碰撞时反复试同一个名字。 |
| 显式替换属于用户保存 | 显式更新把来源设为 `user`；自动 add/update 均受精确遗忘阻挡，显式写入成功后才撤销对应阻挡。遗忘按归一化哈希匹配，原始历史、现有模型上下文及同义改写仍有各自语义。 |
| 先保住替换内容，再考虑自动删除 | 反思先做非删除操作，替换写入被拒、失败或目标冲突时保留原项。删除前复核实际存活的替代项，精确去重可能返回一个已经存在的条目。仍有同描述条目存活时，不为该描述留下删除阻挡。改写后的等义内容仍可能重复，跨文件部分成功仍可发生。 |
| 游标只能确认实际提交的连续批次 | 正常长窗口按清洗后大小选取完整交流，逐批推进 entry 游标。活跃会话末尾未获回复的用户消息保留待处理，已结束会话的用户事实可单独反思。单个超大交流仍有采样边界，并记录采样范围。 |
| 会话切换复用持久边界工作 | 压缩和 `/new` 先保存 `.memory-work`，随后异步反思。新会话的全局游标可能已前进，旧快照原子更新剩余素材并保留稳定 ID，完成时写 `.done`。重复入队须保留已有局部进度，尤其是初次发布和重试交错时。 |
| 背景搜索与首轮预算分别约束 | 工作区背景的前言和正文也可检索，省略提示纳入其预算。工位索引优先保留用户与反馈条目，优先条目足够多时仍可能超过目标。观察项到期后在下次反思前清理，读取时仍可能看到。 |

日志应能区分处理范围、拒绝和删除原因。审查日志出错需要独立报警，已提交的正常写入可以继续沿原流程完成。

## 重新投入的条件

- 日志持续出现超大交流采样且遗漏影响工作时，再考虑消息内持久分片。真实工位出现上下文超限时，先辨别常驻索引、单条大记录与 sidecar 模型预算。
- 写入部分成功导致实质重复或损失时，再评估跨文件事务。显式保存或遗忘经常被反思队列拖住时，先测模型耗时和锁等待，再考虑锁外推理与提交前复核。
- 出现跨频道纠正后频繁误用旧事实或到期事实时，再评估索引失效策略和读取 TTL。历史覆盖可按实际查询问题先改扫描范围和过滤，历史任务归档已可检索，语义重排仍需独立价值证据。
