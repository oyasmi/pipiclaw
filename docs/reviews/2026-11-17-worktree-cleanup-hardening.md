# Worktree 回收修复与测试整理

审查基点：`15275b0`（0.9.6-beta.2）。

## 修复的故障

1. Git index 损坏、命令超时或输出超限时，旧检查逻辑返回 `dirty: false` 和初始提交，结算误判为无改动，再用强制删除及递归删除清走未提交成果。
2. 外部 `follow_up` 复用旧 run 的工作树。旧 run 结算满 24 小时后，GC 不检查使用者，会删除已经合并但仍被续接进程使用的干净工作树。

## 实现

- 检查失败不产生“干净且未推进”的虚假结果，保留工作树、分支及 `.worktree.json`，并记录检查失败日志。
- 删除使用普通 `git worktree remove`。Git 对工作树锁或检查后新增文件的拒绝不会被 `--force` 或递归删除绕过；失败后保留元数据供重试。
- 回收在第一次 Git 检查之前取得独占清理保护，直到删除及元数据处理结束后才释放。保护与派发共用进程级路径冲突规则，检查与删除之间不会放进新委派。
- 写委派与验收分别沿用写租约、共享读租约；普通只读委派登记 `use`，允许与写委派并行，但阻止回收。重启恢复按 `mutates` 和 `purpose` 重建相同语义。
- 已结束 worker 可在自己的租约仍存在时清理无改动工作树；清理保护不释放 run 的租约，仍由运行管理器负责结算。
- 暂时在用的工作树等待下轮回收，不消耗保留警告标记；无法确认状态与未合并、未提交改动分别呈现。

## 测试整理与准入

单元用例从 1030 增至 1035（+5）：

- 将原先塞在 verifier 用例内的任务工作树交付独立出来（+1），保留提交信息进入任务记录及合并前后的回收验证。
- 将无改动结算独立到领域测试，并增加“不能提前释放 owner 租约”的断言（+1）。
- Git 检查失败时的文件与恢复元数据保全（+1）。旧测试只覆盖正常 Git 状态，无法捕获此数据丢失路径。
- Git 拒绝删除时保留工作树并允许重试（+1），覆盖递归删除绕过 Git 保护的风险。
- 清理与目录使用者的互斥、异步窗口及失败后的释放（+1），覆盖单次冲突查询无法发现的检查后竞态。

删除了混合测试中的重复 clean/dirty 夹具与可变 mode 驱动；dirty 工作树的真实写入、隔离及持久化仍由现有 A16 覆盖，领域测试保留检查修复后拒绝回收 dirty 工作树的断言。verifier 的时间轮询改为显式到达/释放信号。

确定性 e2e 从 71 增至 72（+1）：新增受控 CLI 子进程的首次委派 → Git 提交 → 持久化结算和唤醒 → 续接 → 到期回收 → 续接完成 → 回收重试链。原 A16 只有内置 worker，不经过外部续接与 GC，无法捕获这个跨模块故障。子进程使用 Codex 协议夹具及本机 socket 握手控制生命周期，模型侧使用 mock provider 的 hold/arrived/release；不使用延时猜测执行窗口，也不调用真实模型或 Codex 服务。
