**会话压缩第一、二批修复交付记录**

改动范围是停止与恢复、同步压缩的期限与性能、边界记忆工作的持久化。第三批“后台生成会话摘要并在安全边界采用候选结果”没有在这次引入；其后续交付见 [第三批记录](2026-10-22-compaction-background.md)。

**最终行为**

- 手动、预防性、SDK 阈值和溢出压缩通过 `agent/session/compaction.ts` 的公开扩展钩子生成摘要。快照持久化、模型路由、鉴权、推理和重试共享 60 秒总期限；20 秒没有有效输出则取消。重试至多一次，尊重 retry.enabled，不会重置总期限。扩展失败显式返回 cancel，禁止 SDK 吞掉异常后继续无期限的默认压缩。
- 摘要独立使用 off thinking 和最多 4096 tokens 的输出预算，不改变主会话的 thinking。历史与回合前缀合为一次摘要请求；不完整或空摘要不会替换原会话。连续压缩显式继承累计文件操作记录，保留原始会话 JSONL。
- 预防性入口遵守 compaction.enabled；session slash command 不先自动压缩，`/compact` 的要求只交给一次正式压缩。steer 入队不再调用会中止主工作的手动 compact。失败或用户取消后，自动压缩对当前 SDK session 冷却 30 秒，手动命令可立即重试。没有足够空间且恢复失败时，直接给出 /compact、/new 等下一步，不继续盲目提交大请求。
- `/stop` 超过 3 秒未收敛时，钉钉退休旧 runner 并更换 transport 队列，终端替换执行引用，保持原活动会话。旧订阅/投递关闭，旧回合不能结束新回合或投递迟到的任务结果。DingTalk 与 TUI 的 `/new` 都绕过忙碌执行建立新会话；终端的控制操作不排在普通输入后面，连续重置按顺序提交。
- 压缩前只原子持久化 `.memory-work/<conversation>/<id>.json`，不等 dot 的记忆队列或模型整理。压缩结束后启动后台 reflect；首次加载 runner、调度器和退出 flush 都能恢复待处理工作，关闭空闲定时维护不取消已落盘的边界工作。后台写入仍经过同一个 dot 队列/跨进程锁，失败保留快照并退避，完成后留下很小的 `.done` 回执，重复入队不会重复推理。
- sidecar 的超时包含鉴权，重试共用剩余预算；超时/取消后才返回的凭据不能启动新的模型请求。费用仍归入 sidecar，压缩请求也记录独立的关联 id 和模型用量。

**边界和限制**

这里的期限是事件循环可以调度时的应用级限制，不是进程或文件系统完全停顿时的 OS 保证。外部委派仍由 run manager 管理，`/stop` 不取消已派发的外部运行。

待 reflect 快照、检查点和完成回执可恢复；多文件记忆写入沿用现有的逐文件原子提交。若进程在记忆部分写入之后、检查点之前崩溃，恢复仍可能重放该次整理，不能宣称跨多文件的 exactly-once 事务。

保留了大历史输入的头尾限幅机制，但移除了“中间内容已经保存到长期记忆”的错误暗示；原始 JSONL 仍可通过 session_search 查找。分段摘要、更精细的语义保留、动态阈值以及后台候选摘要属于后续工作。

**测试准入与变异检查**

Unit 用例从 912 增至 916（净增 4）：两个压缩钩子场景分别覆盖快照/鉴权不返回时的期限、显式取消及迟到请求隔离；另一个覆盖 disabled 开关被 SDK 手动入口绕过。这些分支不在原有纯预算函数测试中，普通完成的 e2e 也无法覆盖不合作的鉴权 Promise。第四个覆盖后台工作目录发现失败：原本目录读取在错误边界外，会让后台生命周期产生未处理的 rejection，原有 provider 失败场景无法覆盖；以真实 ENOTDIR 复现，修复前红、修复后绿。既有 sidecar、记忆生命周期、停止测试直接扩展，没有为移动的文件增加测试。

确定性 e2e 从 59 增至 62（净增 3）：新增压缩期间记忆 worker 挂起但下一轮仍可执行、真实 daemon SIGKILL 后恢复边界工作、TUI 忙碌时建立新会话三个不同的跨模块缺口。旧 /stop 场景扩展为旧 transport callback 不返回时仍能处理新请求，并在旧回合迟到完成后验证新回合仍忙碌。连续两次压缩还检查累计文件记录，没有增加单独场景。

| 故意破坏 | 检出的失败 |
