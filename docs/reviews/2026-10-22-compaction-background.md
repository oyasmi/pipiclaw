**会话压缩第三批：后台准备与安全采用**

实现与验证截至 2026-10-23（UTC+8）。承接 [第一、二批交付](2026-10-22-compaction-implementation.md) 及 [机制审查](2026-10-22-session-compaction.md)。基于当前安装的 pi SDK 1.2.0 公开接口实现，没有在后台调用会中止主任务的 `session.compact()`，没有新增 SDK 私有字段依赖。

**执行与预算**

- `agent/session/compaction.ts` 每个当前会话最多保留一个候选。新请求前、工具批次全部结果落盘后检查；在有效窗口扣除 SDK 输出预留及 4096 tokens 误差余量后，以剩余输入预算的 70% 启动后台摘要。已有 provider usage 已含 system/tools，不再次相加；SDK usage 未知时使用完整 canonical projection 的估值。
- 有余量时主会话继续，新消息不会默认取消候选。只有到达硬预算才等待已有候选的剩余期限；候选失败、无效或收益不足且仍没有空间时停止提交大请求，并提供 `/compact`、`/new` 恢复入口。不会等待失败候选后再串行重开一份完整期限的摘要。
- 摘要使用独立执行配置，保留上一批的 60 秒总期限、20 秒无有效输出期限、off thinking、每次最多 4096 输出 tokens。鉴权、快照、所有分段和每段至多一次的重试共用期限。

**并发与持久化**

`compaction-snapshot.ts` 在 SDK canonical projection 上选择完整工具调用/结果的切点。候选固定 session 对象与 manager、sessionId、模型身份、baseCompactionId、throughEntryId，以及捕获时整个原始分支的 SHA-256。生成期间允许在分支尾部追加消息或提示状态；采用时重验前缀，任何原始前缀修改、context_edit、分支切换、另一份压缩或模型变化都会令候选失效。聊天与任务会话重绑也显式取消。

采用仅在 idle 或工具批次结束进行：先用 SDK 的 inMemory SessionManager 预览相同 compaction，再使用公开 appendCompaction + refreshContext 提交。原 JSONL 保留，生成期间追加的完整尾部仍进入下一请求。至少释放 min(8192, 窗口×4%) tokens、减少 10%，并降到准备阈值以下才接受；否则保留原投影并冷却，避免低收益反复失效缓存。

`/stop`、`/new`、退出、runner 退休、会话/分支/模型切换会取消候选；后台推理即使迟到也失去采用权限。运行中关闭自动压缩也会在下一次检查/采用前取消。手动 `/compact` 明确取消旧候选，按用户要求重新生成；SDK 阈值/溢出路径可采用仍有效的候选。

SDK 的追加会先改变内存索引、再写磁盘。若提交抛错，当前 session 被隔离且停止，不继续使用可能只存在于内存中的投影；原始已落盘历史保持，交由既有重建/新会话恢复机制处理。这里没有把 SDK 追加包装成跨进程或跨多文件事务。

候选本身只驻留内存；重启丢弃未采用候选，从原始历史重新准备。已经采用的摘要作为标准 compaction 持久化，不会在重启后再次采用同一候选。边界记忆范围仍由上一批的 `.memory-work` 持久化工作恢复。

**输入覆盖与可回查性**

`compaction-input.ts` 仅缩减摘要请求中的大工具结果和长工具参数，不修改主会话原始消息。先合并多段工具文本再统一限幅，保留工具结果头尾、原文哈希、JSONL 路径及 entry id/时间定位；相同载荷用哈希引用去重。这样会保留位于大工具结果末尾的错误，并可回查被覆写前的工具内容。

普通消息经过完整序列化后按不超过 48000 prompt units / 144000 字符的片段递进摘要，保留 256 字符重叠。上一片段检查点作为下一片段的已有摘要，原始中段不再被头尾截取任意删除。最多四片，超出、空摘要、length 截断或期限耗尽均失败保留原会话。SDK 序列化仍会省略 thinking；这与 SDK 标准压缩一致，工具协议和原始 thinking 块仍由 canonical projection 处理。

达到硬预算而等待时，用户会收到可执行 `/stop`、`/new` 的提示；后台准备本身不占用用户控制入口。退出时在等待记忆保存之前取消后台摘要。

摘要只提供语义检查点，不保证每个细节都进入检查点。session_search 有既有的单条扫描上限；引用另提供原 JSONL 定位，不能把搜索无匹配当成历史不存在。

**观察与测试准入**

日志区分 started、ready、adopted、offered_to_sdk、discarded、low_gain 与失败，并带 operationId、sessionId 和时长；自有提交记录前后估值，交给 SDK 的结果只有实际持久化后才记录 adopted。摘要明确要求活动任务所需的小型 JSON、字段名、类型、标志和冻结值逐字保留，不能改名或猜值。分段和重试的模型费用逐请求记入 sidecar，最终 compaction usage 累加；被丢弃候选的成本也保留。

新增行为探针 `M-compaction-02`：把目标、冻结标识、布尔禁止项放在 66000 字中文消息的中段，按所选模型真实窗口触发后台准备，等待真实 ready，再在下一请求边界采用，最后检验重新写入的交接文件。判分同时要求后台 compaction 落盘、精确字段正确和压缩后发生文件操作。含合法、非法、JSON 等价、仅手动摘要、提前完成文件等独立控制；不会以文件恰好早已存在冒充续接质量。
