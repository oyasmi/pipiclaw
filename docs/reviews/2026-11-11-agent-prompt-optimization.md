## 范围

基于 `c1f3a76387fb0d8fa156496c8f0a2e3b8b6adc34`。按用户要求删除 8 份岗位模板及 `agents/scout.md`，保留 10 份外部能力条目。既有模型、推理档、CLI 命令、权限声明和预算保持不变；工作区已安装配置不在本次修改范围。

## 改动理由

| 位置 | 原有风险 | 本轮修改与预期收益 |
|---|---|---|
| agents description | 无任务分布和版本依据的跨供应商排名；把只读当成低成本、把简单当成低风险 | 改为候选用途；低成本档要求做法明确、易检查、易恢复，高档用于关键取舍或难验证工作；区分模型能力与实际输入链路 |
| agents 共用正文 | 执行者不继承主代理的输入来源规则；证据位置未充分限定适用版本；反复检查缺少停止条件 | 保留九条交付约定，合并重复的真实性要求，补来源边界、对应产物与未验证项、复用已核实检查和达标即交付 |
| agent-delegation | 选档依据偏粗；不同模型容易被当作独立性的充分条件；聊天附件不会自动传给执行者 | 先筛选可用性、输入和执行边界；优先独立依据与取证方法；要求明确图片路径和链路支持 |
| task-lead 立项 + 常驻提示词 | 常驻提示词把等待结果列为立项条件，与临时异步委派规则冲突 | 统一为需要跨回合持续管理目标、验收、预算和多步进展；单次作业或委派不因异步而立项 |
| task-lead 步骤记录 | “做了什么”可能只形成活动流水账，恢复时重复调查 | 记录本步新增结论、证据、改动与检查、未决问题和下一动作／真实等待来源；不复抄历史 |
| task-lead 验收 + 运行时验证说明 | 检查结论未限定版本；FAIL 混合缺陷与检查受阻；换检查者可能重复全量检查 | 交代版本、覆盖项与证据缺口；区分缺陷修复和补验证条件；已有证据仍适用时复用，保留必需检查和 PASS/FAIL 协议 |
| memory-and-learning | 永久存储容易被误解为事实永久有效，或被用来扩大授权 | 在应用记忆处核对主人、范围、时效；易变事实另行核实，记忆不扩大授权 |
| 示例说明、用户文档、命令示例和模板测试 | 删除模板后留下无效安装建议和加载用例 | 清理活跃文档引用，命令示例使用现存条目；保留能力模板加载与权限元数据检查，删除已移除模板专属用例 |

后台作业、事件调度、附件交付、运行时导航四份 playbook 保持原样。本轮没有新增状态、协议枚举或固定岗位流水线。
