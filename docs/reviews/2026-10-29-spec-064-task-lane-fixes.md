## 范围与取舍

| 问题 | 处理 |
|---|---|
| R1 | 输入先追加、后尝试 steer；日志稳定 id 随输入正文进入会话，读取实际会话 JSONL 后追加 input_ack。开始步骤和 SDK 入队都不消费输入；恢复可以重投。 |
| R2 | 当前用户等待没有 ask_delivered 时补发；失败至少退避一分钟，重启继续补发。复用任务状态、日志和车道定时器，不引入通用 outbox。 |
| R3 | 扫描、连续推进和 work 唤醒最终都经过步骤入口检查；beginStep 在任务锁内再检查绑定和开关。冻结时延后对账；当前步骤允许收尾并计入实际并发，解冻后的实际步骤并发仍受 3/5 限制。 |
| R4 | 请求中止后保留三秒宽限；仍不退出则退休 runner、暂停后续执行并通知部署者。旧执行退出前保留占用，拒绝恢复；取消先封住新步骤，未确认退出不归档。 |
| R5 | 状态变化记录带完整 frontmatter 检查点；Markdown 的 revision 与状态、成本原子提交。日志先提交，读取及对账重放未应用检查点。settle 按 ref 去重，run/job 接收失败保留重试资格。 |
| R6 | 归档或取消失败不发成功回执，暂停并提供排障下一步；关闭意图留在日志中，重启恢复时不让模型重新执行普通步骤。 |
| R7 | 管理器查询在任务锁外完成，随后在锁内复核最新状态、正文、版本及真实步骤生命周期，再归档。避免任务锁与结算管理器锁互相等待。 |
| R8 | 所有步骤入口检查退避和总开关；work 路径不能绕过。 |
| R9 | 内置 edit/write 对当前工位任务文件的完整读取、修改、写入过程使用任务锁；写入前恢复落后快照，整文件写入只替换正文并保留最新运行时文件头。 |
| R10 | runTaskLane 表示扫描并等待本轮 drive 静止，允许多步；taskMessage 是向指定任务追加真实输入后推进车道。移除无效 at；waitFor 推进车道，消息命令使用 /tasks msg。行为场景要求至少一步，预算场景仍要求精确步数；任务证据评分读取 step_end。 |

**R4 不提供物理停止的硬上界。** 退休 runner 能阻止新的工具调用、会话事件和后续步骤，不能撤销已经发出的任意工具副作用。未退出的旧步骤仍被跟踪，不创建同任务的替代执行。真正的硬上界需要可终止的执行隔离，本次不引入进程执行框架。

日志仍沿用三个分片和 4 MiB 大小目标。轮转不能删除未消费输入、结算去重记录和最近恢复依据；必要时活动日志超过大小目标，关闭后随任务归档。这是保留事实的空间成本，不添加缓存或新的状态文件。

## 验证

- 单测优先扩展原场景：输入认领后恢复、结束提交后恢复、未消费 steer、work 退避、提问补发、归档失败、完成竞态、冻结与不响应 abort。任务文件编辑加入既有跨进程锁场景。用例数保持 974，净增 0。
- deterministic e2e 从 68 增至 69，净增 1。新增 task-recovery 的风险是旧进程消失后，日志与快照不一致导致用户等待、账务或输入失去恢复机会；现有正常执行与同进程重启场景不能证明此机制。
- 新进程场景在测试进程中拦住真实快照 rename，日志已提交时用 IPC 告知父进程，随后 SIGKILL；不依赖目录权限或当前 uid，也不向产品添加故障注入接口。恢复检查磁盘状态、步数、提问确认和供应商请求数；再验证开始记录已提交、输入尚未进入会话时的 SIGKILL。
- 变异检查：关闭 checkpoint 重放，用户等待恢复断言失败；恢复“最后 step 之后才算输入”的边界，供应商请求缺失 UNSEEN_AFTER_CLAIM，断言失败。两次均已恢复代码。
- DESK-3 扩展为在 held 步骤期间换绑，释放后不能请求第二步，绑回后才继续。去掉 drive 与 beginStep 的绑定检查后，此用例失败；变异已恢复。
