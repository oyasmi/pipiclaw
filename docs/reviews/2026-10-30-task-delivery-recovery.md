# 2026-10-30：任务交付与崩溃恢复修复

## 问题确认

当前版本独立复现了两类归档崩溃：日志移走后 SIGKILL、归档说明发布后 SIGKILL；活动说明仍在，重试因归档文件存在而失败。半行 JSONL 后追加的第一条完整记录会被连带跳过。汇报返回失败、工作项仍待办时也能够完成归档。未知执行费用被写成估算的零美元，美元检查无法反映缺失部分。

两次日报具体的耗时差异没有取得远端原始证据，不能认定是同一种计算错误。修复统一由运行时生成历时，明确包含排队与等待。远端 `/Users/qy/logs` 配置未在本次 checkout 中操作。

## 实现

- `tasks/archive.ts` 用 `.closing/<id>.json` 保存关闭说明快照与日志分片指纹。归档完整发布前保留活动数据；同一次提交重试验证已有目标，继续发布和清理，不覆盖冲突。活动说明已经删除、恢复记录还在的窗口也能恢复。恢复先于正常调度，恢复期间禁止内置文件工具和领域写入改动任务。
- JSONL appender 的任务专用尾部保护在锁内读取末尾字节，先隔开无换行残片。保留残片；显式任务记录查询和体检提示损坏位置。不重写日志，也不对每次普通追加增加 fsync。
- `tasks/delivery.ts` 保存待发报告及关闭回执。报告落盘先于网络发送；确认与任务记录关联。失败按 1 分钟起、最多 15 分钟退避，重启后继续。每条消息有独立投递锁，网络等待不持有任务锁；同一任务的报告保持顺序。消息确认提交处单独同步任务记录后，才删除重试文件。
- 关闭意图绑定当前步骤最后一份报告；送达确认前只进行运行时重试，不运行新模型步骤，也不完成归档。关闭前再次核对 DoD、工作项与在途工作；能够由负责人修复的检查失败作为持久输入交回下一步。进入收尾后不再接受会被遗落的新指示。
- 完成回执在归档前准备、归档后发送；回执重试不需要扫描历史归档。回执使用持久关闭时间、步数、费用和工作项数据，分别列出放弃项。负责人自身与委派的价格已知性分开记录，避免把同一笔未知委派成本在负责人步骤和委派结算里重复计数。未知费用保留为 `unknownCostCount`，已知费用小计与步数约束继续生效；不把美元预算宣称为严格账单上限。
- 任务 brief 明示 `<deskDir>/work/<taskId>/`，手册说明自定义 cwd 与外部绝对路径不会自动隔离。未增加 OS 沙箱、shell 命令识别、通用迁移器或自动改写外部路径。

正常路径增加的是任务日志尾部的常数大小读取、低频报告提交的持久写入，以及关闭时一次性归档复制和校验；没有每 token 工作、历史归档热扫描或网络失败触发的额外模型调用。手册依旧按需加载：task-lead 从 2713 增至 2993 prompt units（+280），runtime-orientation 从 1675 增至 1750（+75）；这些 units 不是计费 token。

## 测试准入

单测净增 3：两个消息持久化场景覆盖失败退避、投递顺序、换绑限制，以及远端接受已经落盘但日志确认失败后的去重；原有工具测试把发送视为一个返回布尔值的端口，无法证明这段新持久协议。另一个场景覆盖工具接受关闭后、运行时提交前说明被修改的窗口，验证重新检查与负责人可恢复推进。其余扩展既有日志、费用、文件锁、完成门控和用户文案场景。

确定性 e2e 净增 2：旧用例只覆盖步骤日志/快照恢复与正常投递，不能覆盖关闭过程中源文件与归档的关系，也不能证明发送失败或确认缺口的跨进程恢复。新增场景走真实 bootstrap → 工具 → 运行时 → 磁盘/渠道，断言持久状态、分片完整性、投递次数及提供方请求数量；不评价模型措辞。

故障通过测试进程拦截真实文件发布/清理、IPC 屏障和 SIGKILL 注入，没有产品故障开关，没有 sleep。时钟推进控制投递重试窗口。归档在用户取消的关闭记录已提交而快照尚未建立、日志发布、说明发布、活动说明清理四个位置杀进程；投递覆盖明确失败及远端接受、尚未写本地确认的缺口。后者允许至少一次投递的重复，但保持同一消息内容。

已执行并恢复的变异：

1. 禁用车道的归档恢复：重启后活动说明仍在，磁盘状态断言变红。
2. 跳过报告队列落盘：失败后没有持久重试记录，断言变红。
3. 关闭日志尾部保护：紧随残片的完整记录丢失，日志用例变红。
4. 禁用“暂停之后已经提交关闭”的恢复准入：用户取消在提交关闭记录后退出，重启仍停在暂停，磁盘状态断言变红。
