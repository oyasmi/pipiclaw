# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`AGENTS.md` is the source of truth for domain boundaries and engineering rules — read it too. This file adds the commands and the cross-file architecture that AGENTS.md does not spell out.

## Commands

- `npm run check` — full gate: `lint` + `typecheck` + `arch` + `deadcode` (knip) + `test`. Run this before considering a change done.
- `npm run arch` — `scripts/check-architecture.mjs`: module dependency direction, file-level cycles, the 800-line file budget, dangling relative paths (including `vi.mock` strings, which `tsc` does not check) and file references in the docs. Its baseline (`scripts/architecture-baseline.json`) may only shrink. `scripts/move-modules.mjs` moves files and rewrites every import for you.
- `npm run test` — unit/integration tests (Vitest). Excludes `test/e2e/**`.
- Single test file: `npx vitest run test/memory-lifecycle.test.ts`
- Single test by name: `npx vitest run -t "creates a distinct session id"`
- `npm run test:e2e` — deterministic full-stack layer (`test/e2e/deterministic/`): real bootstrap, real memory/queue/delivery, but the model is an in-process scripted mock. Zero network, zero API cost, well under 90s. Run it when you touch runtime / memory / delegation / the command plane (spec 048).
- `npm run test:e2e:live` — the real-model smoke cases (`test/e2e/live/`): follows `~/.pipiclaw/settings.json`, costs tokens, manual / nightly.
- `npm run typecheck` — `tsc --noEmit` against `tsconfig.json` (the config with `noUnusedLocals`/`noUnusedParameters`; `tsconfig.build.json` is emit-only).
- `npm run lint` — Biome (format + lint); autofix with `npx biome check --write .`.
- `npm run deadcode` — knip. Configured with `ignoreExportsUsedInFile`, so an `export` used only inside its own file is not flagged; a *genuinely* unused export must be deleted or its `export` dropped, not suppressed.
- `npm run build` — `tsc -p tsconfig.build.json`, copies Markdown assets with `scripts/copy-md-assets.mjs`, then chmods `dist/main.js` (the `pipiclaw` bin).

Node `>= 22.19.0`.

## Tests

- Follow `AGENTS.md`'s **Unit-test admission and size control** rules. Existing features default to no net increase in unit cases: extend a valuable scenario or replace a weaker one first. Justify any increase with a distinct failure mode, its impact, why existing unit/e2e coverage is insufficient, and the count delta. A spec 054-style move/split/rename changes imports and fixtures, not the number of tests.
- Omit tests that mirror private structure, pin template values/field order/copy, check an echoing forwarding mock, or recreate third-party setup just to assert the setup worked. Keep a boundary matrix in its owning domain and use deterministic e2e for full-stack wiring. Do not disguise growth or pruning by combining unrelated cases, skipping tests, or narrowing discovery.
- Every test must earn its place by covering something that can actually break: branching logic, edge cases, boundaries, concurrency, contracts, security guards, regressions. Do **not** add obvious low-value tests — asserting the literal substrings of a rendered help/status/label string, `new X() instanceof X` smoke checks, echoing a constant back, or re-testing a one-line pure formatter with no branches. If a change to the code under test could only ever break the test by also being an intentional edit to that same text, the test is a change-detector, not a safety net.
- Deterministic e2e follows the same no-net-growth default and requires an identified cross-module gap plus a mutation check for new cases. Assert real provider/disk/delivery/run effects; use `hold.arrived` for provider barriers. A daemon-crash claim requires a separate process, and completion checks must wait for persistence/settlement. `npm run test:e2e` builds the daemon fixture before running it.
- When touching runtime, memory, or DingTalk behavior, cover the behavior change — but with a test that would fail on a real regression, not one that pins cosmetic output.

## Git

- Write good commit messages: a concise imperative subject line (e.g. `feat: add proxy routing for LLM requests`), optionally followed by a blank line and a body that explains *why* the change was made. Match the existing conventional-commit style (`feat:`, `fix:`, `chore:`, `ci:`, `docs:`, etc.).
- **Never add a `Co-Authored-By:` trailer** (or any similar signature) to commit messages.

## Architecture

Pipiclaw is a long-lived runtime that wraps the `@earendil-works/pi-coding-agent` SDK (a fork of `@mariozechner/pi-coding-agent`) and drives it from DingTalk. The module layering — what each directory owns and what it may import — is the table in `AGENTS.md` (enforced by `npm run arch`); this section covers the flows that cross those modules.

**Transport → agent → delivery flow**
1. `src/runtime/bootstrap.ts` loads config and wires the transports, durable dispatch, task/event/memory services, background jobs, and sub-agent run persistence; `src/runtime/ingress.ts` is the one inbound pipeline every transport hands its messages to (binding, stop, `/new`, busy messages, runtime commands, queueing; each turn runs through `src/runtime/turn-run.ts`) and `src/runtime/shutdown.ts` the ordered teardown. `src/main.ts` is intentionally a thin entrypoint that just calls `bootstrap`.
2. `src/dingtalk/bot.ts` (a facade over `connection.ts`, `inbound.ts`, `cards.ts`, `media.ts`, `access-token.ts`) receives Stream-mode events; `src/dingtalk/delivery.ts` builds the `ChannelContext` (the transport-neutral delivery contract in `src/channel/channel-context.ts`: `respond`, `respondInThread`, AI Card streaming). The Web API transport (`src/webapi/`, an OpenAI Responses-shaped HTTP/WebSocket server, spec 061) is the second implementation of the `Transport` contract (`src/channel/transport.ts`); a transport hands every inbound message to `src/runtime/ingress.ts` and answers through `ChannelContext.emit(TurnEvent)` / `finish(TurnOutcome)`. The terminal (`src/tui/`) is not a transport but a client of the Web API's local socket (`state/webapi/api.sock`); with no daemon running `bootstrapEmbedded` starts a runtime inside the terminal process with only that socket switched on.
3. Before anything else the runtime resolves the channel's binding through `src/runtime/desk-runtime.ts` (`DeskRuntime`, the daemon's one authority on `desk-bindings.json` and which desks are active). App-home initialization creates the built-in `default` desk. Authorized human ingress persists an absent binding to `default` before attachments or command routing; existing bindings (including unavailable targets) are preserved. Reads and synthetic wakes never auto-bind. The terminal opens `default` unless `--desk` is given (its first message on a new conversation is `/desk bind <desk>`); a synthetic wake is admitted only while its channel is still bound to the wake's `desk` (`runEventTurn` in `turn-run.ts`; durable dispatch refuses desk-less events). Each bound channel gets one `ChannelRunner` (`src/agent/channel-runner.ts`) for its `DeskConversation` (desk directory as the default cwd, optionally overridden by desk.json; sessions in the channel's conversation directory), created by `src/agent/runner-factory.ts` and cached in `src/runtime/bootstrap.ts`; `/desk bind` releases it (cache removal, then `dispose`, whose final reflect lands in the old desk). `ChannelRunner` is the turn facade: it owns `TurnStateMachine` and the run pipeline (`agent/turn/turn-pipeline.ts`, `turn-finish.ts`), while `agent/session/session-host.ts` owns the SDK session, tools, system prompt and extensions. It streams the turn through the transport-neutral `ChannelContext`.
4. `src/agent/session/session-events.ts` translates SDK session events into progress/AI-Card updates.
5. The stateless report commands (`/desk /events /tasks /status /usage /context /subagents /skills`) are one handler, `src/commands/router.ts`, shared by every transport — add a command there, not in a transport. Each delegates to the owning domain's `commands.ts`.

**Concurrency model (important, spans several files)**
- Per channel, turns are serialized by the **`ChannelQueue`** (`src/runtime/channel-queue.ts`, owned by the ingress): a channel processes one message at a time while still accepting `/steer`, `/followup`, `/stop` mid-turn. Busy state itself has a single owner: the runner's turn state machine (`TurnPhase` in `src/agent/types.ts`; transports call `beginTurn`/`endTurn`, everything else derives from `isBusy()`/`getTurnStatus()`). `src/agent/turn/run-queue.ts` is a different, per-run queue that serializes *outbound delivery calls* (progress updates to the DingTalk API) within a single turn.
- Memory writes are serialized **per desk** (spec 058, INV-8) on `src/shared/serial-queue.ts` plus the cross-process `desk-<desk>/.locks/memory.lock`. `src/memory/desk-memory-queue.ts` exposes a *shared singleton* queue keyed by desk name so `lifecycle` (boundary reflect), `reflect-job` (background reflect), `memory_save` and `/memory` never race on the same desk's files, whichever of its channels they come from — do not inline it or key it by channel.
- Task writes go through `withTaskMutation` (in-process reentrant queue plus `desk-<desk>/.locks/task-<id>.lock`), and `desk.json` read-modify-writes hold `.locks/desk-json.lock`. These short cross-process locks (`src/shared/file-lock.ts`) are what let processes share a desk; nothing locks a whole desk. One runtime process per app home is enforced separately by `state/daemon.lock` (`src/runtime/daemon-lock.ts`): the daemon, or the runtime the terminal embeds when no daemon runs, holds it for its whole life.
- Config/state files are written via `src/shared/atomic-file.ts` (write-temp-then-rename).

**Long-horizon tasks (`src/tasks/`, specs 051/052)** — three things, do not flatten back into one:
- The **contract** `tasks/<id>.md` (Goal / DoD / Work Items, a 4 KB target the runtime never rewrites, injected whole into every step), the **loop log** `tasks/<id>.jsonl` (append-only step / dispatch / settle / expiry / close records — the source of the step brief's `<task_board>`), and the **ticket** in frontmatter (what will wake this task, and by when). A task is a one-off project the model leads; there is no cycle or `schedule`.
- `ticket.ts` is the only place a `Ticket` comes into existence: `resolveTicket` validates the claim (a `work` ticket needs a delegation or job bound to this task still in flight) and stamps the `by` backstop. Three kinds only: `time`, `work` (any bound run/job settling redeems it), `ask`. Anything writing `ticket` directly is a defect — it would recreate the "parked with nothing to redeem it" failure the whole mechanism exists to remove.
- `store.ts` owns the idempotent transitions (`redeemTicket`, `expireTicket`, `pauseTask`, `resumeTask`); `budget.ts` is the two-dimension (steps/usd, including bound delegation cost) stop; `bound-work.ts` is how `SubAgentRunManager` and `DeskJobManager` write `dispatch`/`settle` records at registration and settlement, guarded by `taskAccounted`/`taskLogged`. `purpose=verify` verdicts are recorded information, not a gate — there is no attestation.
- A task step runs in the task's own session (`tasks/.sessions/<id>.jsonl`), bound via `ChannelRunner.bindTaskSession`; delegations and jobs started there bind to the task automatically. It is still an ordinary channel-queue item, so busy state, `/stop` and delivery are unchanged — only which session file the turn is bound to differs.
- Every task records its delivery `channel` in frontmatter (set at creation: the creating turn's channel, or the spawning event's). While that channel is not bound to the task's desk the task driver skips the task entirely — no maintenance, budget check or dispatch — and it resumes when the channel is bound back (spec 058, D8).
- `events/` is a separate subsystem and the only time source; each desk has its own `events/` and watcher (started on activation, stopped when the desk loses its last binding), and an event whose `channelId` is not bound to the desk is skipped with `channel_not_bound`. An event carries either chat `text` or a `task` template; `runtime/task-spawn.ts` (injected into the watcher) creates one instance per occurrence (`<event>-<YYYYMMDD>-<HHmm>`, idempotent) and skips with a receipt while the previous instance runs. Events never read or write task files.

**Delegation (`src/subagents/`)** — workspace roles select internal execution (`internal/run.ts`) or an external `claude-code` / `codex-cli` / `exec` harness (`external/dispatch.ts`); `dispatch.ts` is the shared admission path and `tools/subagent.ts` the model-facing adapter. `SubAgentRunManager` alone owns settlement, usage, leases, persistence, and completion wake; preserve its idempotency flags. Run and job managers are per desk (`runs.get(desk)`, `DeskJobManager`, records under `state/subagent-runs/<desk>/` and `state/jobs/<desk>/`); a delegation's default `workingDirectory` is the desk directory. A completion wake whose channel is no longer bound to the desk is suppressed but still redeems the task's `work` ticket. External runs are async/detached and reconciled by the runtime; an embedded (terminal) runtime stops with the terminal, so it does not re-adopt after exit. `mutates: write` leases overlapping working directories, and `/stop` does not cancel runs.

**Memory subsystem (`src/memory/`, spec 050)** — three things, do not flatten back into one:
- Desk memory (shared by every channel bound to the desk): one fact per file in `memory/<name>.md` (frontmatter metadata), generated index `MEMORY.md` (never hand-written — rebuilt by `store.ts` on every write). A daily `journal/YYYY-MM-DD.md`, written only by the background reflect pass. `log.jsonl`/`context.jsonl` are cold storage.
- `store.ts` owns the one-fact-per-file mechanics (apply ops, tombstones, secret scan, atomic write, index rebuild); `search.ts` is the Jaccard similarity used for `memory_save` conflict detection and `memory_search`; `index-budget.ts` tiers the index when it's too big for the first-turn injection (D4); `render.ts` builds the `<memory_bootstrap>` block.
- Compaction uses `agent/session/compaction.ts`: background immutable-prefix candidates, safe idle/tool-batch adoption with preserved tail, bounded hard-budget recovery, and explicit cancellation on hook failure. `compaction-snapshot.ts` owns provenance/gain checks; `compaction-summary.ts` owns bounded inference and full-coverage segmented input. Before compaction, `memory/boundary-work.ts` durably queues the source window; inference runs after compaction and pending work resumes on boot even with idle maintenance off. `/stop` recovery retires a generation and replaces its transport queue while preserving the active session.
- `reflect.ts` is the **single** background LLM pass (replacing v1's three jobs), invoked both at session boundaries (via `lifecycle.ts`) and on the idle scheduler (`reflect-job.ts`); `scheduler.ts` + `maintenance-gates.ts` + `maintenance-state.ts` + `maintenance-tuning.ts` form the *gated, scheduled* pipeline around it. Each of these has dedicated tests — keep them as separate, single-responsibility units.
- `sidecar-worker.ts` runs LLM-backed memory work off the main turn.

**Tools (`src/tools/`)** are the capabilities handed to the main agent and internal sub-agents (`bash`, files, web, memory, skills, tasks, events, jobs, delegation). Pipiclaw-owned filesystem/command/network tools go through `src/security/` guards, with blocked actions written to the audit logger. File tools (`read`, `edit`, `write`, `send_media`) go through `src/file-store.ts`'s `FileStore` port straight onto `node:fs`; command tools (`bash`, `grep`) go through `src/executor.ts`'s `Executor`. Both are bound to the same `resolvedPath` `guardPath` returns — a path is resolved once and that value is what actually gets opened, never re-derived (spec 044, D1.1). External agents are separate host processes and bypass those guards: their role command, CLI sandbox, host account, and environment are the real boundary; `mutates` is not a permission control. `write.ts` remains a thin wrapper over shared `write-content.ts`. A tool's parameter set is exactly the fields its one call shape needs — nothing conditionally required by another field's value, nothing a deployer should have decided once instead (spec 046): the long-running task mechanism is a handful of tools (`task_list`/`task_create`/`task_update`/`task_close`/`task_log`, plus `task_step_end` registered only inside a task session) rather than one `action`-dispatched tool, and delegation is `subagent` (a configured role; no override fields) plus `subagent_inline` (a one-off; carries every field a role file would otherwise supply), gated by `tools.subagentInline.enabled`.

**Skills (`src/skills/`)** explicitly load `workspace/skills/` and the server user's `~/.agents/skills/` (spec 063). Valid workspace skills override shared names; rejected workspace overrides fall back with diagnostics. The prompt, `/skill:name`, `/skills` and the read-only `skill` tool share discovery and name resolution. SDK auto-discovered skills never merge into the final catalog. File-tool writes refresh the current session; external edits require `/reload`.

**Config & state live outside the repo**, under `APP_HOME_DIR` (`~/.pipiclaw`, overridable via `PIPICLAW_HOME`). Paths are centralized in `src/paths.ts` (`channel.json`, `auth.json`, `models.json`, `settings.json`, `tools.json`, `security.json`, plus `workspace/` and `state/`). Desks live in `workspace/desk-<desk>/` (layout in `src/desk/paths.ts`), bindings in `workspace/desk-bindings.json`, DingTalk routing metadata in `state/dingtalk/conversations.json`, the Web API's socket and conversations in `state/webapi/`, the terminal client's last conversation per desk in `state/tui/conversations.json`, and the single-runtime lock in `state/daemon.lock`. `channel.json` has `dingtalk` and `webapi` sections, each with an `enabled` switch; offline upgrades are documented in `docs/channel-migration.md`. Data upgrades are offline operator work documented in `docs/desk-migration.md`; the runtime only reads current desk records and never runs migration or old-layout detection. `src/index.ts` is the public library barrel, deliberately minimal (spec 035): it supports embedding the daemon (`bootstrap`, `DingTalkBot`, `ChannelContext`, path constants, `PipiclawSettings`) and nothing else. Keep those names stable; do not add to it — every export there is also a knip blind spot, since it is a knip entry point.

`settings.json` accepts only product intent — booleans, enums, and model references. Numeric thresholds (intervals, budgets, backoffs, confidence bars) are code constants; retired keys are listed in `RETIRED_SETTINGS_KEYS` in `src/config/settings.ts` and warned about on load.

## Docs
